## 第 0 课 · 概念 + 环境(先读后敲)

**核心认知(背下来)**:

- 模型的知识**冻结在训练那天**。你的笔记、公司的文档,它从来没见过——你问,它只能编
- 上下文窗口有限:把所有文档全塞进 prompt = 装不下 + 烧钱 + 资料一多模型"看不过来"(大海捞针)
- **RAG(检索增强生成)= 先检索,后生成**:文档切块 → 向量化入库 → 按问题的相似度取出最相关的几块 → 塞进 prompt → 模型基于资料回答。**不是微调:不改模型参数,只是"考试时允许翻书"**
- **embedding(向量化)**:把一段文字压成一个定长的浮点数组(语义坐标)。意思相近的文字,坐标就挨得近——"语义"从此可以算距离了
- **Rerank(重排序)**:向量检索是"粗筛"(快但常混进像而不相关的),rerank 是"精排"(逐个候选打相关性分)——第 8 课实战
- **上下文工程**:对话越攒越长怎么管理?截断、摘要、混合三种策略——第 6 课实战。Agent 开发里 90% 的工程不是"怎么调 LLM",而是"怎么把上下文组织好"
- 发给模型的才是它"知道"的:阶段 1 的窗口裁剪、阶段 2 的工具结果喂回,都是这条世界观的局部应用

**Java 视角提前挂钩子**:手写向量库 ≈ `List<记录>` + 线性扫描;真向量库(chromadb/Milvus/PGVector)≈ 加了索引的存储引擎——对外接口一模一样。阶段 7 你会用到 PGVector(你熟悉的 PostgreSQL 装个插件)。

## 第 1 课 · 00_embedding.py — 文字变成向量

**目标**:调一次 embedding 接口,亲眼看到"一段文字 = 一串浮点数"。

**新概念**:
- `input` 直接传**列表**,一次请求批量向量化——省请求,将来建库全靠它
- 返回的 `data` 和 `input` 按顺序一一对应(`item.index` 就是下标)
- **不同模型的维度不同**:embedding-3 默认 2048 维,bge-m3 是 1024 维——所以后面永远 `len(vec)` 动态取,别写死

## 第 2 课 · 01_similarity.py — 手算余弦相似度

**目标**:不借助任何库,用纯 Python 算出两个向量的余弦相似度,并按"和问题的语义接近程度"给句子排序。

**新概念**:
- **余弦相似度 = 两个向量夹角的余弦**,范围 -1~1,越接近 1 越相似。公式:点积 ÷ (长度 × 长度)——Java 里就是两个 `double[]` 的双层循环
- 为什么用余弦不用欧氏距离:比较的是**方向**(语义朝向)而不是绝对位置,长度归一化后更稳
- 检索的本质:**问题也是一段文字 → 也向量化 → 谁和它夹角小谁胜出**

```python
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

embed_client = OpenAI(
    api_key=os.environ.get("EMBEDDING_API_KEY"),
    base_url=os.environ.get("EMBEDDING_BASE_URL"),
)
EMBEDDING_MODEL = os.environ.get("EMBEDDING_MODEL", "embedding-3")


def cosine(vec_a, vec_b):
    """余弦相似度:点积 / (|a| * |b|),越接近 1 语义越近"""
    dot = sum(a * b for a, b in zip(vec_a, vec_b))
    norm_a = sum(a * a for a in vec_a) ** 0.5
    norm_b = sum(b * b for b in vec_b) ** 0.5
    return dot / (norm_a * norm_b)


sentences = [
    "我爱吃火锅",
    "火锅是我最喜欢的食物",
    "今天股市大跌",
    "股票又跌了,好心疼",
]
query = "今晚吃什么好呢?"

# 查询和候选一次性批量向量化,顺序和 input 一一对应
resp = embed_client.embeddings.create(model=EMBEDDING_MODEL, input=sentences + [query])
vecs = [item.embedding for item in resp.data]
query_vec = vecs[-1]                      # 最后一条是查询

scored = [(cosine(query_vec, v), s) for s, v in zip(sentences, vecs[:-1])]
scored.sort(reverse=True)                 # 按分数从高到低

print(f"查询:{query}\n")
for score, s in scored:
    print(f"{score:.4f}  {s}")
```

**自测/实验**:
1. "吃"相关的两句是不是排前面了?和无关句的分数差多少?
2. 把 `query` 换成"行情怎么样",排名变了吗?
3. 思考:语料 10 条时线性扫一遍毫无压力;10 万条呢?(这就是真向量库的"索引"存在的意义)

## 第 3 课 · 02_vector_store.py — 你的第一个"向量数据库"

**目标**:60 行手写一个带持久化的向量库:`add` 入库、`search` 检索、JSON 落盘、重启可复用。写成一个小对话程序,能反复查。

**新概念**:
- 向量库的全部灵魂 = **一个列表 + 一次线性扫描 + 排序取前 k**。真向量库只是把"扫描"换成索引、把"列表"换成数据库,**对外的 add/search 长得和这一模一样**
- **建库是慢操作(要调 API),查询是快操作(纯算术)**——所以文档向量要缓存落盘,这是所有向量库的通用设计
- `@classmethod load`:类方法当"工厂",文件存在就恢复,不存在就给空库

```python
import json
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

embed_client = OpenAI(
    api_key=os.environ.get("EMBEDDING_API_KEY"),
    base_url=os.environ.get("EMBEDDING_BASE_URL"),
)
EMBEDDING_MODEL = os.environ.get("EMBEDDING_MODEL", "embedding-3")
STORE_FILE = "vectors.json"


def cosine(vec_a, vec_b):
    """同第 2 课"""
    dot = sum(a * b for a, b in zip(vec_a, vec_b))
    norm_a = sum(a * a for a in vec_a) ** 0.5
    norm_b = sum(b * b for b in vec_b) ** 0.5
    return dot / (norm_a * norm_b)


def embed_texts(texts):
    """批量向量化。一次最多 32 条,防止超出平台单请求上限"""
    vectors = []
    for start in range(0, len(texts), 32):
        batch = texts[start:start + 32]
        resp = embed_client.embeddings.create(model=EMBEDDING_MODEL, input=batch)
        vectors.extend(item.embedding for item in resp.data)
        print(f"  已向量化 {start + len(batch)}/{len(texts)} 条")
    return vectors


class SimpleVectorStore:
    """你的第一个向量库:一个列表 + 线性扫描 + JSON 落盘"""

    def __init__(self):
        self.items = []   # 每个元素 {"text": ..., "vector": [...]}

    def add(self, text, vector):
        self.items.append({"text": text, "vector": vector})

    def search(self, query_vector, top_k=2):
        scored = [(cosine(query_vector, it["vector"]), it["text"]) for it in self.items]
        scored.sort(key=lambda pair: pair[0], reverse=True)
        return scored[:top_k]

    def save(self, path):
        with open(path, "w", encoding="utf-8") as f:
            json.dump(self.items, f, ensure_ascii=False)

    @classmethod
    def load(cls, path):
        store = cls()
        if os.path.exists(path):
            with open(path, "r", encoding="utf-8") as f:
                store.items = json.load(f)
        return store


if __name__ == "__main__":
    store = SimpleVectorStore.load(STORE_FILE)
    if not store.items:
        knowledge = [
            "公司的年假一共 10 天,入职满 3 年加 5 天",
            "报销要在 OA 系统提交,每周四统一打款",
            "健身房在 3 楼,工作日 7 点到 22 点开放",
            "停车位需要向行政申请,每月 300 元",
            "会议室预订用飞书,超过 1 小时要写明事由",
            "加班打车费 22 点之后实报实销",
        ]
        for text, vec in zip(knowledge, embed_texts(knowledge)):
            store.add(text, vec)
        store.save(STORE_FILE)
        print(f"(知识库已建立并保存到 {STORE_FILE})")
    else:
        print(f"(从 {STORE_FILE} 加载了 {len(store.items)} 条向量,没花一分钱)")

    while True:
        q = input("\n问一句(直接回车退出): ").strip()
        if not q:
            break
        q_vec = embed_texts([q])[0]
        for score, text in store.search(q_vec, top_k=2):
            print(f"  {score:.4f}  {text}")
```

**自测/实验**:
1. 问"上班迟到扣钱吗"(库里没有)——看最高分掉到多少,感受"没有就是没有"
2. 第二次启动时观察"(从 vectors.json 加载…没花一分钱)"——为什么文档向量能缓存、问题向量不能?
3. 打开 `vectors.json` 看看:6 条就这个体积,1 万条呢?(阶段 7 的 PGVector 就是来解决这个的)
4. 把 `top_k` 改成 1 和 4 各跑一次,体会 k 的取舍:少了怕漏,多了塞给模型的噪音就多
5. **进阶(可选)**:`pip install chromadb`,用它的 `collection.add / query` 把手写库替换掉,对比两者接口——你会发现唯一的区别是它内置了 embedding 模型和索引。但先别急,手写一遍才知道它替你干了什么

## 第 4 课 · 03_chunking.py — 长文档切块

**目标**:真实文档是长篇 Markdown,不能整篇当一个向量。学两种切块策略,并**实测**:同一个问题,哪种切法检索得更准。

**新概念**:
- **chunk 太大** → 一个向量揉了多个主题,检索不准,塞进 prompt 也浪费;**太小** → 上下文残缺,答案断了胳膊少条腿
- 固定滑窗切块:按字符数硬切,`overlap`(重叠带)兜住被拦腰斩断的句子
- 按 Markdown 标题切:标题是**天然的语义边界**(你们的学习手册就是现成语料)。注意跳过代码块里的 `#`——那是 Python 注释,不是标题

```python
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

embed_client = OpenAI(
    api_key=os.environ.get("EMBEDDING_API_KEY"),
    base_url=os.environ.get("EMBEDDING_BASE_URL"),
)
EMBEDDING_MODEL = os.environ.get("EMBEDDING_MODEL", "embedding-3")


def chunk_by_size(text, size=400, overlap=50):
    """固定长度滑窗:简单粗暴,overlap 是给被切断句子留的重叠带"""
    chunks = []
    start = 0
    while start < len(text):
        chunks.append(text[start:start + size])
        start += size - overlap
    return chunks


def chunk_by_heading(text):
    """按 Markdown 标题切。跳过代码块里的 # 注释行"""
    chunks, current = [], []
    in_code = False
    for line in text.splitlines():
        if line.strip().startswith("```"):
            in_code = not in_code
        if not in_code and line.startswith("#") and current:
            chunks.append("\n".join(current).strip())
            current = []
        current.append(line)
    if current:
        chunks.append("\n".join(current).strip())
    return [c for c in chunks if c]


def cosine(vec_a, vec_b):
    """同第 2 课"""
    dot = sum(a * b for a, b in zip(vec_a, vec_b))
    norm_a = sum(a * a for a in vec_a) ** 0.5
    norm_b = sum(b * b for b in vec_b) ** 0.5
    return dot / (norm_a * norm_b)


def embed_texts(texts):
    """同第 3 课(分批 32)"""
    vectors = []
    for start in range(0, len(texts), 32):
        batch = texts[start:start + 32]
        resp = embed_client.embeddings.create(model=EMBEDDING_MODEL, input=batch)
        vectors.extend(item.embedding for item in resp.data)
    return vectors


# ---- 语料:直接拿阶段 2 的学习手册当知识库 ----
DOC_PATH = os.path.join("..", "02_agent", "学习手册.md")
with open(DOC_PATH, "r", encoding="utf-8") as f:
    doc = f.read()

size_chunks = chunk_by_size(doc, size=400, overlap=50)
head_chunks = chunk_by_heading(doc)
print(f"全文 {len(doc)} 个字符")
print(f"固定滑窗(400/50):{len(size_chunks)} 块")
print(f"按标题切:{len(head_chunks)} 块:")
for c in head_chunks:
    print("  -", c.splitlines()[0][:40])

# ---- 同一个问题,两种切法各建一个索引,看谁检索得准 ----
question = "毕业考要写哪些功能?"


def build_index(chunks):
    return list(zip(chunks, embed_texts(chunks)))


def top_k(index, query, k=3):
    q_vec = embed_texts([query])[0]
    scored = [(cosine(q_vec, v), c) for c, v in index]
    scored.sort(key=lambda pair: pair[0], reverse=True)
    return scored[:k]


print(f"\n问题:{question}\n")
print("== 固定滑窗 top3 ==")
for score, c in top_k(build_index(size_chunks), question):
    print(f"  {score:.4f}  {c[:50]!r}")
print("== 标题切块 top3 ==")
for score, c in top_k(build_index(head_chunks), question):
    print(f"  {score:.4f}  {c[:50]!r}")
```

**自测/实验**:
1. `size` 改成 100 和 1000 各跑一次:太碎、太肥分别什么表现?
2. `overlap=0` 时,关键句刚好跨在切块边界上会发生什么?
3. 哪种切法检索得更准?为什么?(标题是"人工标注好的语义边界"——切块的核心不是算法,是**顺着文档结构来**)

## 第 5 课 · 04_rag_chat.py — RAG 聊天机器人诞生(整合)

**目标**:把前四课拼成完整流水线:**启动建库(带缓存)→ 提问检索 → 资料塞 prompt → 带来源流式回答**。这是本阶段的核心作品。

**先准备语料**(命令行):

```bash
mkdir docs
cp ../01_LLM/学习手册.md ../02_agent/学习手册.md docs/
# 再自己手写一个 docs/notes.md,放点两本手册里都没有的内容(比如你的个人备忘)
```

**新概念**:
- RAG 的"R"(检索)发生在**你的代码里**,不是模型的能力——模型只负责基于你塞的资料说话
- **引用编号**:资料带 `[1] [2]` 编号塞进去,要求回答标注来源——这是对抗"编造"最简单有效的手段
- 提问每次都要重新 embedding(问题千变万化),文档向量只建一次(内容不变)——**缓存的是慢且不变的部分**

```python
import json
import os

from dotenv import load_dotenv

load_dotenv()

# ---- 两个客户端:聊天走 DeepSeek,向量走智谱 ----
chat_client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL"),
)
CHAT_MODEL = os.environ.get("MODEL_NAME")

embed_client = OpenAI(
    api_key=os.environ.get("EMBEDDING_API_KEY"),
    base_url=os.environ.get("EMBEDDING_BASE_URL"),
)
EMBEDDING_MODEL = os.environ.get("EMBEDDING_MODEL", "embedding-3")

DOCS_DIR = "docs"           # 知识库语料目录
STORE_FILE = "vectors.json"
TOP_K = 4

SYSTEM_PROMPT = (
    "你是资料问答助手。回答只允许依据【资料】里的内容,"
    "用到资料的地方标注来源编号如 [1];"
    "资料不足以回答时,直接说\"资料里没有\",禁止编造。回答保持简短。"
)


# ========== 向量部分:第 1~3 课的成果 ==========
def cosine(vec_a, vec_b):
    dot = sum(a * b for a, b in zip(vec_a, vec_b))
    norm_a = sum(a * a for a in vec_a) ** 0.5
    norm_b = sum(b * b for b in vec_b) ** 0.5
    return dot / (norm_a * norm_b)


def embed_texts(texts):
    vectors = []
    for start in range(0, len(texts), 32):
        batch = texts[start:start + 32]
        resp = embed_client.embeddings.create(model=EMBEDDING_MODEL, input=batch)
        vectors.extend(item.embedding for item in resp.data)
        print(f"  已向量化 {start + len(batch)}/{len(texts)} 块")
    return vectors


class SimpleVectorStore:
    """第 3 课的向量库,多存一个 source 字段用于标注来源"""

    def __init__(self):
        self.items = []   # 每个元素 {"text", "source", "vector"}

    def add(self, text, vector, source=""):
        self.items.append({"text": text, "source": source, "vector": vector})

    def search(self, query_vector, top_k):
        scored = [(cosine(query_vector, it["vector"]), it) for it in self.items]
        scored.sort(key=lambda pair: pair[0], reverse=True)
        return scored[:top_k]

    def save(self, path):
        with open(path, "w", encoding="utf-8") as f:
            json.dump(self.items, f, ensure_ascii=False)

    @classmethod
    def load(cls, path):
        store = cls()
        if os.path.exists(path):
            with open(path, "r", encoding="utf-8") as f:
                store.items = json.load(f)
        return store


# ========== 切块部分:第 4 课的成果,两条策略配合 ==========
def chunk_by_size(text, size=400, overlap=50):
    chunks = []
    start = 0
    while start < len(text):
        chunks.append(text[start:start + size])
        start += size - overlap
    return chunks


def chunk_by_heading(text):
    chunks, current = [], []
    in_code = False
    for line in text.splitlines():
        if line.strip().startswith("```"):
            in_code = not in_code
        if not in_code and line.startswith("#") and current:
            chunks.append("\n".join(current).strip())
            current = []
        current.append(line)
    if current:
        chunks.append("\n".join(current).strip())
    return [c for c in chunks if c]


def chunk_text(text, max_len=500):
    """先按标题切,超长的段落再用滑窗细切"""
    chunks = []
    for section in chunk_by_heading(text):
        if len(section) <= max_len:
            chunks.append(section)
        else:
            chunks.extend(chunk_by_size(section, size=400, overlap=50))
    return chunks


# ========== 建库与检索 ==========
def load_documents():
    """读 docs 目录下所有 .md/.txt,返回 [(文件名, 全文)]"""
    docs = []
    for name in sorted(os.listdir(DOCS_DIR)):
        path = os.path.join(DOCS_DIR, name)
        if os.path.isfile(path) and name.lower().endswith((".md", ".txt")):
            with open(path, "r", encoding="utf-8") as f:
                docs.append((name, f.read()))
    return docs


def build_store():
    """全量重建:切块 → 向量化 → 入库 → 落盘"""
    pending = []   # (块文本, 来源文件名)
    for name, text in load_documents():
        for chunk in chunk_text(text):
            pending.append((chunk, name))
    if not pending:
        print(f"({DOCS_DIR}/ 目录是空的,先放几个 .md/.txt 进去)")
        return SimpleVectorStore()

    print(f"共 {len(pending)} 块,开始向量化…")
    vectors = embed_texts([text for text, _ in pending])
    store = SimpleVectorStore()
    for (text, source), vec in zip(pending, vectors):
        store.add(text, vec, source)
    store.save(STORE_FILE)
    print(f"(知识库已重建:{len(pending)} 块 → {STORE_FILE})")
    return store


store = SimpleVectorStore.load(STORE_FILE)
if not store.items:
    store = build_store()


def retrieve(question, top_k=TOP_K):
    """检索:问题向量化 → 相似度排序 → 取前 top_k"""
    q_vec = embed_texts([question])[0]
    return store.search(q_vec, top_k)


# ========== 对话循环 ==========
print(f"RAG 助手已启动 | 知识库 {DOCS_DIR}/ 共 {len(store.items)} 块 | /rebuild 重建索引,exit 退出")
while True:
    try:

    except (KeyboardInterrupt, EOFError):

        break

    if not question:

        print("AI: 知识库是空的,先往 docs/ 里放几个 .md 吧")
        continue

    # 命中日志:来源 + 分数,排查检索质量全靠它
    print("(命中:" + ", ".join(
        f"{item['source']}·{score:.2f}" for score, item in hits
    ) + ")")

    # 检索到的资料编号后塞进 prompt —— RAG 的"R"到这里就完成了
    context = "\n\n".join(
        f"[{i + 1}] (来源:{item['source']})\n{item['text']}"
        for i, (_, item) in enumerate(hits)
    )

    print("AI: ", end="", flush=True)
    stream = chat_client.chat.completions.create(
        model=CHAT_MODEL,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},

        ],
        stream=True,
    )
    for chunk in stream:
        delta = chunk.choices[0].delta.content if chunk.choices else None
        if delta:

## 第 6 课 · 05_context_trim.py — 上下文工程:给 Agent 裁历史

**目标**:Agent 跑久了,messages 越攒越长(对话历史 + 工具记录),最终撑爆窗口。本课解决阶段 2 毕业考的进阶思考题——**带工具调用的历史,不能按"条"裁,要按"轮"裁**,再多就用摘要压缩。

**新概念**:
- **API 的铁律:assistant(带 tool_calls) 必须紧挨着它的 role=tool 结果**。按条裁剪会把"点菜"和"菜"拆散 → 400 报错
- **轮次(round)**:一轮 = user + 它引发的 assistant/tool 消息。裁剪单位改成"轮",点菜和菜天然在同一轮里,拆不散
- 上下文工程三种策略,本课一次配齐:
  - **截断(Truncation)**:只留最近 N 轮——简单粗暴,丢早期上下文;按轮截断是它的正确姿势
  - **摘要(Summarization)**:旧轮次让模型压缩成一段话——省 token,丢细节
  - **混合(Hybrid)**:旧轮摘要 + 最近 N 轮原文——工业界主流,本课最终方案
- **token 预算**:调模型前先估算(`len//2` 粗算,阈值留余量),超了才压缩——压缩是**按需的**,不是每轮都做

```python
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL"),
)
MODEL = os.environ.get("MODEL_NAME")

SYSTEM_PROMPT = "你是一个能使用工具的助手。"


def split_rounds(messages):
    """把消息列表切成轮次:每轮从 user 开始,后面跟着它引发的 assistant/tool 消息。
    开头的 system(以及 user 出现前的所有消息)自成一轮。
    关键性质:assistant(tool_calls) 和它的 role=tool 结果永远落在同一轮,拆不散。"""
    rounds = []
    for m in messages:
        if m["role"] == "user" or not rounds:
            rounds.append([m])       # 新一轮开始
        else:
            rounds[-1].append(m)     # 归入当前轮
    return rounds


def trim_rounds(messages, keep_rounds):
    """只保留 system + 最近 keep_rounds 个完整轮次(截断策略,按轮)"""
    rounds = split_rounds(messages)
    head, body = rounds[0], rounds[1:]
    kept = body[-keep_rounds:]
    return [m for r in [head] + kept for m in r]


def is_broken(msgs):
    """这串消息直接发给 API 会 400 吗?
    规则:每条 role=tool 之前,必须'隔着最近的点菜消息'——
    即从上一条非 tool 消息到现在,必须见过带 tool_calls 的 assistant。"""
    armed = False
    for m in msgs:
        if m["role"] == "assistant" and m.get("tool_calls"):
            armed = True
        elif m["role"] == "tool":
            if not armed:
                return True          # 收到了没人点过的菜
        else:
            armed = False
    return False


def count_tokens(messages):
    """粗算 messages 总 token(len//2,中文略低估,阈值留余量即可;
    要精确用 tiktoken,但学习阶段没必要)"""
    total = 0
    for m in messages:
        if m.get("content"):
            total += len(m["content"]) // 2
        if m.get("tool_calls"):
            total += len(str(m["tool_calls"])) // 2
    return total


def make_tool_round(user_text, tool_name, tool_result, call_id):
    """造一轮'点菜'消息,凑假历史用(结构照抄真实返回)"""
    return [
        {"role": "user", "content": user_text},
        {"role": "assistant", "content": None,
         "tool_calls": [{"id": call_id, "type": "function",
                         "function": {"name": tool_name, "arguments": "{}"}}]},
        {"role": "tool", "tool_call_id": call_id, "content": tool_result},
        {"role": "assistant", "content": f"已通过 {tool_name} 完成:{tool_result}"},
    ]


# ---- 构造一段 5 轮假历史(两轮用了工具)----
history = [{"role": "system", "content": SYSTEM_PROMPT}]
history += [
    {"role": "user", "content": "我叫 WangZZZ,记住我"},
    {"role": "assistant", "content": "好的 WangZZZ!"},
]
history += make_tool_round("几点了?", "get_current_time", "2026-09-20 10:00:00", "call_1")
history += [
    {"role": "user", "content": "把'买菜'写进 todo.txt"},
    {"role": "assistant", "content": "已写入 todo.txt"},
]
history += make_tool_round("读一下 todo.txt", "read_file", "买菜", "call_2")
history += [
    {"role": "user", "content": "我叫什么名字?todo 里写的什么?"},
    {"role": "assistant", "content": "你叫 WangZZZ,todo 里是'买菜'。"},
]

# ---- 本地演示:按条裁 vs 按轮裁 ----
rounds = split_rounds(history)
print(f"共 {len(history)} 条消息,{len(rounds)} 轮(含 system),估算 {count_tokens(history)} tokens\n")

naive = [history[0]] + history[1:][-4:]          # 阶段 1 的老办法:按条裁
print(f"按条裁(留最近 4 条):{len(naive)} 条,发出去会 400 吗?→ {is_broken(naive)}")

trimmed = trim_rounds(history, keep_rounds=2)    # 本课方案:按轮裁
print(f"按轮裁(留最近 2 轮):{len(trimmed)} 条,发出去会 400 吗?→ {is_broken(trimmed)}")
print("\n--- 按轮裁后实际发送的内容 ---")
for m in trimmed:
    content = (m.get("content") or "(tool_calls 点菜)")[:30]
    print(f"  [{m['role']}] {content}")


# ---- 混合策略:超预算时,裁掉的旧轮次不丢弃,压缩成摘要保留 ----
def summarize_old_rounds(messages, keep_rounds):
    """窗口装不下时:旧轮次 → LLM 压缩成一条摘要消息 → 垫在最前面。
    上下文工程核心思想:先降维(摘要),实在不行才丢弃。"""
    rounds = split_rounds(messages)
    head, body = rounds[0], rounds[1:]
    if len(body) <= keep_rounds:
        return messages

    old, kept = body[:-keep_rounds], body[-keep_rounds:]
    transcript = "\n".join(
        f"[{m['role']}] {m.get('content') or '(点菜)'}"
        for r in old for m in r
    )
    resp = client.chat.completions.create(
        model=MODEL,
        messages=[
            {"role": "system", "content":
             "把对话压缩成 150 字以内的摘要,必须保留:人名、数字、文件名、"
             "已完成的操作等所有关键事实。只输出摘要本身。"},
            {"role": "user", "content": transcript},
        ],
    )
    summary = resp.choices[0].message.content

    trimmed = list(head)
    trimmed.append({"role": "system", "content": f"此前对话的摘要:{summary}"})
    trimmed += [m for r in kept for m in r]
    return trimmed


def ensure_budget(messages, max_tokens, keep_rounds=2):
    """调模型前的预算护栏:没超限原样返回,超了才触发混合压缩"""
    used = count_tokens(messages)
    if used <= max_tokens:
        print(f"(token 预算 {used}/{max_tokens},不压缩)")
        return messages
    print(f"(token 预算 {used}/{max_tokens},触发混合压缩)")
    return summarize_old_rounds(messages, keep_rounds)


print("\n=== 混合策略:超预算才压缩 ===")
compressed = ensure_budget(history, max_tokens=1, keep_rounds=2)  # 故意给 1,必触发
print(f"压缩后:{len(compressed)} 条,估算 {count_tokens(compressed)} tokens,is_broken={is_broken(compressed)}")
for m in compressed:
    content = (m.get("content") or "(tool_calls 点菜)")[:40]
    print(f"  [{m['role']}] {content}")

# 真发一次验证:拿着"摘要 + 最近 2 轮"问一个被裁掉的事实
probe = compressed + [{"role": "user", "content": "我叫什么名字?"}]
final = client.chat.completions.create(model=MODEL, messages=probe)
print(f"\n问'我叫什么名字?':{final.choices[0].message.content}")
```

**自测/实验**:
1. 把 `naive` 真发给 API 跑一次,记下报错原文(阶段 2 报错速查表里的那一条)——这就是进阶思考题让你"试着触发一次"的东西
2. `keep_rounds=1` 时,按轮裁实际发送的 6 条是什么?
3. 摘要会丢什么?(精确措辞、无关细节)什么场景绝对不能容忍丢?(提示:你敢让摘要替你记住密钥吗?)
4. 注意看:按轮裁之后"我叫 WangZZZ"那一轮被裁掉了,但混合压缩版答对了吗?——体会"降维不等于失忆"

> 小坑:个别平台不允许多条 system 消息。若报错,把摘要那条 `{"role": "system"}` 改成 `{"role": "user"}` 一样能跑。

## 第 7 课 · 06_query_rewrite.py — 检索优化:先改写,再检索

**目标**:解决第 5 课留下的问题——"那第 2 点展开讲讲"这种**带指代、省略主语**的口语问题,直接拿去检索必挂。先让模型把问题改写成完整独立的一句话,再检索。

**新概念**:
- **改写器是独立的一次 LLM 调用**:输入"对话上下文 + 最后的问题",输出"检索友好的问题"——小模型、低温度就够,生产上用最便宜的档
- 这是一切"检索前优化"的原型:同义词扩展、混合检索(关键词+向量)都是往这条流水线上加工序

## 第 8 课 · 07_rerank.py — Rerank:粗筛之后再来一道精排

**目标**:向量检索只看"语义像不像",经常把"像但不相关"的块排到前面。实现工业界标准流程:**向量检索粗筛 top-10 → rerank 精排取 top-3 → 塞 prompt**。

**新概念**:
- **粗筛快而糙**:向量检索有索引,百万级文档也是毫秒级,但只算"语义距离"
- **精排准而慢**:对每个候选单独打相关性分,10 个候选就要算 10 次——所以它永远排在粗筛后面,**不能直接当检索用**
- 先粗筛后精排的本质:**把贵的计算留给少数候选**。Java 视角:这就是"SQL 分页先捞 20 条,再逐条调重量级逻辑深加工"
- 本课用 **LLM 当 reranker**:一次调用给 10 个候选打分、输出 JSON——正好复用阶段 1 的结构化输出。生产上会换专门的 rerank 模型(见本课末尾"生产方案")

```python
import json
import os

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

chat_client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL"),
)
CHAT_MODEL = os.environ.get("MODEL_NAME")

embed_client = OpenAI(
    api_key=os.environ.get("EMBEDDING_API_KEY"),
    base_url=os.environ.get("EMBEDDING_BASE_URL"),
)
EMBEDDING_MODEL = os.environ.get("EMBEDDING_MODEL", "embedding-3")

STORE_FILE = "vectors.json"   # 先跑过第 5 课,直接复用建好的库

RERANK_PROMPT = (
    "你是相关性评审员。给你一个问题和若干候选资料,"
    "给每个候选和问题的相关性打 0~10 分"
    "(10 = 直接回答了问题,5 = 沾边,0 = 完全无关)。"
    '只返回 JSON:{"scores": [8, 0, 3, ...]},顺序和候选编号一致。'
)


def cosine(vec_a, vec_b):
    """同第 2 课"""
    dot = sum(a * b for a, b in zip(vec_a, vec_b))
    norm_a = sum(a * a for a in vec_a) ** 0.5
    norm_b = sum(b * b for b in vec_b) ** 0.5
    return dot / (norm_a * norm_b)


class SimpleVectorStore:
    """同第 5 课,原样搬过来"""
    def __init__(self):
        self.items = []

    @classmethod
    def load(cls, path):
        store = cls()
        with open(path, "r", encoding="utf-8") as f:
            store.items = json.load(f)
        return store


def embed_texts(texts):
    """同第 5 课"""
    vectors = []
    for start in range(0, len(texts), 32):
        batch = texts[start:start + 32]
        resp = embed_client.embeddings.create(model=EMBEDDING_MODEL, input=batch)
        vectors.extend(item.embedding for item in resp.data)
    return vectors


def llm_rerank(question, candidates):
    """让模型给每个候选打相关性分,按分排序。
    比向量检索慢、贵,但判断'真相关'比'语义像'准得多"""
    listing = "\n".join(f"[{i}] {text[:120]}" for i, text in enumerate(candidates))
    resp = chat_client.chat.completions.create(
        model=CHAT_MODEL,
        messages=[
            {"role": "system", "content": RERANK_PROMPT},
            {"role": "user", "content": f"【问题】{question}\n\n【候选】\n{listing}"},
        ],
    )
    try:
        scores = json.loads(resp.choices[0].message.content)["scores"]
        assert len(scores) == len(candidates)
    except (json.JSONDecodeError, KeyError, AssertionError):
        scores = [5] * len(candidates)   # 兜底:模型不听话就全给中间分,流程不崩
    ranked = sorted(range(len(candidates)), key=lambda i: scores[i], reverse=True)
    return ranked, scores


# ---- 粗筛 top-10 → 精排 top-3 ----
question = "毕业考要写哪些功能?"

store = SimpleVectorStore.load(STORE_FILE)
q_vec = embed_texts([question])[0]
coarse = store.search(q_vec, top_k=10)          # 粗筛:快、便宜
candidates = [it["text"] for _, it in coarse]
coarse_scores = [score for score, _ in coarse]

print(f"问题:{question}\n")
print("== 粗筛 top10(按向量相似度)==")
for i, (score, item) in enumerate(coarse):
    print(f"  #{i + 1}  {score:.4f}  {item['source']}  {item['text'][:36]!r}")

ranked, scores = llm_rerank(question, candidates)

print("\n== 精排 top3(按 LLM 相关性分)==")
for rank, idx in enumerate(ranked[:3]):
    print(f"  #{rank + 1}  {scores[idx]:>2} 分  {candidates[idx][:50]!r}")
```

**生产方案(LLM 打分的教学版 → 工业版)**:
- 专门的 **rerank 模型**(交叉编码器)才是生产标配。两个不装 torch 的选择:SiliconFlow 的 rerank API(`BAAI/bge-reranker-v2-m3`,一次 HTTP 调用,和 embedding 一样配到 `.env`);或本地跑 `sentence-transformers` 的 `CrossEncoder("BAAI/bge-reranker-base")`(首次下载约 400MB,国内可 `export HF_ENDPOINT=https://hf-mirror.com` 加速)
- 它们对每个 (query, doc) 对输出相关性分,流程和本课完全一样:粗筛 → 打分 → 排序取 top-k

**自测**:
1. 粗筛第 1 名和精排第 1 名一致吗?找出一个被 rerank 提上来/挤下去的块,想明白为什么
2. 为什么不能跳过粗筛、直接 rerank 全库?(每条都要过一次模型,10 万文档 = 10 万次调用)
3. 兜底里"全给 5 分"意味着什么?(rerank 失效,退化成粗筛顺序——**降级而不是崩溃**,和阶段 2 的工具兜底同一个思想)
4. 把问题换成知识库里根本没有的("明天天气"),看精排分数是不是普遍很低——低分是"答不了"的信号,第 5 课的"资料里没有"就靠它把关

## 毕业考 · 08_my_rag_agent.py(闭卷)

**不看手册任何一行**,把本阶段所有技术装进**一个 Agent**——这才是 RAG 在真实系统里的样子:**不是固定流水线,而是模型自己决定查不查**。

要求:

- [ ] 对话式 Agent,记忆跨轮(复用阶段 2 的 `agent_reply` 骨架)
- [ ] 启动时读 `docs/` 下文档建知识库:标题切块 + 超长滑窗细切,向量化存入手写向量库;已有 `vectors.json` 直接加载
- [ ] **`search_knowledge_base` 工具**:模型用 function calling 自己决定调不调。工具内部 = 查询改写(第 7 课)→ 粗筛 top-10 → rerank 精排 top-3 → 带来源编号返回文本
- [ ] 至少再加 2 个工具(复用阶段 2 的 `get_current_time` / `write_file` 即可),验证模型"该查才查"
- [ ] **上下文预算**:每次调 LLM 前 `count_tokens`,超阈值(比如 2000)触发混合压缩(按轮裁剪 + 摘要),打印 token 日志
- [ ] `/reset` `/save` `/load`;保留 `[工具]` 日志和检索命中日志

**过关标准(连续三问)**:
1. "阶段 2 的毕业考要求哪几件事?" → 它自己调 `search_knowledge_base`,回答带来源
2. "现在几点?" → 它**不查知识库**,直接调时间工具——体会 agentic RAG 和固定流水线的区别
3. 连聊 15 轮以上 → token 日志显示压缩发生过,而它还记得你最早告诉它的名字

**提示(只给结构,不给代码)**:
- `search_knowledge_base` 的 JSON Schema:`{"query": {"type": "string", "description": "要检索的问题"}}`——description 写清"查询知识库中的文档资料",模型才知道什么时候点它
- rerank 模型加载一次就够,别每次调用都重建(它和向量库一样是"慢资源")
- 混合压缩的时机:调 LLM **前**检查预算,而不是答完再补

## 常见报错速查

| 报错/现象 | 原因 | 解决 |
|---|---|---|
| `KeyError: 'EMBEDDING_API_KEY'` 或 embedding 请求 401 | `.env` 没配向量那组,或两组 Key 配反了 | 对照第 0 课模板;注意聊天 401 和向量 401 是两回事 |
| 换过 `EMBEDDING_MODEL` 后检索分数异常 | `vectors.json` 里还是旧模型的向量(维度/空间都变了) | 删掉 `vectors.json` 重新 `/rebuild` |
| 429 / `input` 超限报错 | 单次 embedding 条数太多 | `embed_texts` 已按 32 分批,还报就改成 16 |
| `(docs/ 目录是空的)` | docs/ 没放文件,或后缀不是 `.md`/`.txt` | 放文件,确认目录名和后缀 |
| 回答开始编造 | 检索没命中(TOP_K 太小或语料里根本没有) | 先看命中日志的分数;加大 TOP_K;确认资料里真有 |
| 命中的块驴唇不对马嘴 | chunk 太大稀释了语义,或问题太口语 | 调小 `max_len`;上第 7 课改写、第 8 课 rerank |
| `An assistant message with 'tool_calls' must be followed by tool messages...` | 按条裁历史,把点菜和菜拆散了 | 用第 6 课的按轮裁 `trim_rounds` |
| rerank 返回的 JSON 解析失败 | 模型没按格式输出 | 第 8 课兜底已给中间分;检查 RERANK_PROMPT 有没有被改 |
| token 粗算和平台账单对不上 | `len//2` 只是预算护栏 | 估算仅用于"何时压缩"的开关;要精确用 `tiktoken` |
| `vectors.json` 好几 MB | 正常,2048 维浮点数很肥 | 体会为什么生产要专用向量库(阶段 7 的 PGVector) |

**卡住的标准动作不变**:读报错最后一行 → 搜索 → 超 30 分钟,把代码 + 完整报错 + 你跑的原话一起贴给 ZCode。
