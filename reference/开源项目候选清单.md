## 1｜mini-swe-agent —— 最接近你现状的项目 ★首选

`github.com/SWE-agent/mini-swe-agent` · MIT · 20 MB · 8.1k star

**它是什么**：普林斯顿 SWE-agent 团队的"极简主义宣言"——核心 agent 循环约 **100 行**，
无配置文件、无编排框架，SWE-bench Verified 得分 **>74%**（和几百倍体量的框架打平）。

**为什么对你最重要**：
- 它就是"框架只是包了一层"这个论点的**官方实验证据**：一个 while 循环 + shell 工具就够解 GitHub issue。
- 和你 [02_agent/02_mini_agent.py](../02_agent/02_mini_agent.py) 的手写循环**直接 diff**，看生产级 100 行比你多考虑了什么（大概率是：命令超时/输出截断、上下文预算、system prompt 的约束设计）。
- 20 MB 可以整体看完，符合"1 个周末看到全貌"的硬规则。

**读法**：删掉重写再 diff。先自己默写 100 行，再对比。
**Exit**：能回答"为什么它不用 function calling，只靠 shell 就够？"——这是和你阶段 2 认知的最大分歧点。

## 2｜gpt-researcher —— 你毕业考的生产版对照

`github.com/assafelovic/gpt-researcher` · Apache-2.0 · 55 MB · 29.8k star

**它是什么**：跑了好几年的 deep research 产品：planner → 并行搜集 → 去重合并 → 报告生成。
**对照**：你的 [06_multi_agent/research_squad.py](../06_multi_agent/research_squad.py) 毕业考就是它的玩具版。
**看什么**（定点）：
- planner 怎么把主题拆成可并行子任务？动态调整计划的触发条件是什么？
- 并行结果怎么去重/合并？和你 `03_parallel.py` 的差异。
- 它怎么处理搜索工具返回的超长内容（对应 nanobot 设计里的"内容归一化"）。
**Exit**：给 research_squad 补上它有而你没有的 1 个机制（比如子任务去重或失败降级），跑通前后对比。

## 3｜aider —— 生产级 coding agent 的两个独门设计

`github.com/Aider-AI/aider` · Apache-2.0 · 140 MB · 49.3k star ⚠️ 更新放缓，只读不改

**禁止通读**（140 MB）。只定点读两个模块：
- **repo map**：不靠向量检索、靠 tree-sitter + 图排序给 LLM 生成"仓库地图"——这是 RAG 之外的第三种上下文工程，nanobot 没讲。
- **edit format**：让 LLM 稳定改代码的多种格式（diff / whole-file / udiff）与失败重试——结构化输出的最硬核实战，对应你 [04_engineering/structured.py](../04_engineering/structured.py)。
**Exit**：能口述"repo map 和向量 RAG 各自在什么场景赢"，并判断你的项目该不该用（大概率结论是：小项目不需要，能讲清为什么就达标）。

## 4｜letta（MemGPT）—— 记忆的平台化形态（可选）

`github.com/letta-ai/letta` · Apache-2.0 · 294 MB ⚠️ 只定点读 memory/sleep-time 模块

**看什么**：MemGPT 的"内存分页"思想——把上下文窗口当 RAM、把外部存储当磁盘，模型自己决定换页。
与 nanobot 第 3 周（consolidation 记忆）互为印证：一个按页管理，一个按合并管理。
**只在你读完 nanobot 记忆章之后来**，否则两套概念会打架。

## 5｜框架对照组：smolagents + pydantic-ai —— 验证你的论断

你说"框架只是包了一层"，这个论断需要精确到**层**才算懂：

- `smolagents`（7.4 MB，可通读）：CodeAgent 让模型直接写 Python 当工具调用——看它的 1000 行核心，你会发现框架 = **模型适配层 + 工具序列化 + 循环**，共三层，没有魔法。
- `pydantic-ai`（20.3k star）：类型化 Agent + 依赖注入，代表"框架包装"的现代形态（MCP / streaming / retry）。

**Exit**：面试被问"为什么用/不用 LangChain"时，能说出框架真正替你做的 3 件事（多 provider 适配、工具 schema 生成、重试降级）和**不做**的 3 件事（上下文治理、副作用安全、评测）——这比"框架没用"高级一个段位。
