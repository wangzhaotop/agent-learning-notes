## 第 0 课 · 概念 + 环境（先读后敲，30 分钟）

### 核心问题

**生产化 Agent 和 demo 的区别在哪？**

Demo：能跑就行，报错了人工重启，输出格式不对就手动解析。  
生产：稳定性 > 功能性，要求自动重试、结构化输出、可观测、可评测、可扩展。

### 必读材料（3 份，读完再敲代码）

1. **Anthropic《Building Effective Agents》**（阶段 6 读过，复习"When to use agents"章节）  
   https://www.anthropic.com/research/building-effective-agents

2. **Instructor 文档**：Why validate LLM outputs?  
   https://python.useinstructor.com/  
   重点：Retry logic、Validation with Pydantic

3. **mem0 文档**：Memory for AI Agents  
   https://docs.mem0.ai/overview  
   重点：User memory vs Session memory

### 生产化 Agent 的七大支柱

| 支柱 | Demo 做法 | 生产做法 | 本阶段对应课次 |
|------|-----------|----------|----------------|
| **结构化输出** | JSON.parse 报错就重跑 | Instructor 自动重试 + Pydantic 校验 | 第 1 课 |
| **记忆管理** | messages 列表裁剪 | mem0 长期记忆 + 向量检索 | 第 2 课 |
| **服务化** | 本地 `python xxx.py` | FastAPI + SSE 流式 HTTP 服务 | 第 3 课 |
| **向量库** | chromadb 内存模式 | Milvus 持久化 + 分布式 | 第 4 课 |
| **可观测** | print 打日志 | LangSmith / Langfuse 链路追踪 | 第 5 课 |
| **评测** | 人工测试 | LLM-as-judge 自动评分 | 第 6 课 |
| **框架选型** | 手写所有逻辑 | Swarm / Claude SDK 快速搭建 | 第 7 课 |

### 技术选型原则（企业视角）

1. **结构化输出**：Instructor（Pydantic 集成好）> 裸 JSON mode（要自己写重试）
2. **记忆**：mem0（专门做记忆）> 自己写向量检索（轮子太重）
3. **向量库**：
   - 学习 / 小项目：chromadb（轻量）
   - 生产 / 大数据：Milvus（分布式）、Pinecone（托管但收费）
4. **可观测**：LangSmith（官方但收费）、Langfuse（开源可自部署）
5. **Agent 框架**：
   - 快速原型：OpenAI Swarm（轻量，100 行代码）
   - 复杂工作流：LangGraph（你阶段 6 没学，但企业用得多）
   - 手写：阶段 1-6 教会你的，适合定制需求

### 阶段 7 vs 前面阶段的关系

- **阶段 1-6 是地基**：你手写了 Agent 循环、RAG、上下文管理、MCP、多 Agent 编排——这些是**不变的原理**
- **阶段 7 是砖瓦**：用成熟的库/服务把地基变成可交付的房子——Instructor 做的事你在阶段 4 手写过（Pydantic 校验 + 重试），mem0 做的事你在阶段 3 手写过（向量检索记忆），只是现在用专业工具更快更稳

### 自测

1. **为什么不能直接把阶段 6 的 Agent 部署到生产？**  
   提示：没有结构化输出保证、没有可观测、本地文件依赖、没有服务化接口。

2. **Instructor 和阶段 4 的 Pydantic 输出有什么区别？**  
   提示：Instructor 集成了重试逻辑、自动把错误喂回模型、支持流式解析。

3. **mem0 和阶段 3 的 RAG 有什么区别？**  
   提示：mem0 专门存"用户偏好/历史交互"，RAG 存"知识文档"；mem0 有时间衰减、去重。

## 第 1 课 · 提示词模板与模型接入（PDF 3.a / 3.b）

> 从这里开始是「框架篇」。参照《Agent 开发完整学习路线》第 3 章：LangChain 这块很重要。
> 你已经手写过阶段 1-6 的全部核心逻辑，所以这一课的学法只有一个：**每学一个框架概念，就问一句"它替我做了什么"**。

### 目标

1. 用 `ChatPromptTemplate` 写提示词模板：变量插值、Few-shot、上下文占位符
2. 用 `ChatOpenAI` 接入模型（换成任何兼容 OpenAI 协议的平台只改三个参数）
3. 用 LCEL（`|` 管道）把"模板 → 模型 → 解析器"串成一条链
4. **避开本机实测的三个结构化输出大坑**（见下表）

### 核心概念

**① LCEL 管道 = 阶段 1 手写 messages 编排的声明式版**

```python
# 阶段 1 你手写的（命令式）
messages = [{"role": "system", "content": f"你是{role}"}, {"role": "user", "content": q}]
resp = client.chat.completions.create(model=MODEL, messages=messages)

# LangChain 的（声明式）：同一个东西，用 | 串起来
chain = ChatPromptTemplate.from_messages([...]) | llm | StrOutputParser()
chain.invoke({"role": "老师", "question": q})
```

**② 提示词模板三件套**

| 模板 | 解决什么 | 你手写过的对应物 |
|------|----------|------------------|
| `ChatPromptTemplate` | 系统/用户消息 + 变量插值 | f-string 拼 system prompt |
| `FewShotChatMessagePromptTemplate` | 用例子教模型输出格式 | 在 prompt 里手写"示例1/示例2" |
| `MessagesPlaceholder` | 把历史列表插进固定位置 | `messages` 列表拼接（阶段 1 第 3 课） |

**③ 输出解析**：`StrOutputParser`（拿字符串）、`JsonOutputParser`、`PydanticOutputParser`（拿 Pydantic 对象，对照阶段 4 的 `ask_structured`）

**④ ★ 本机实测：结构化输出三种写法的真实结果**

网上教程上来就写 `llm.with_structured_output(MyModel)` —— 在 DeepSeek 上**直接 400**。本机（`deepseek` 思考模型 + openai 3.17.0）实测：

| 写法 | 结果 | 说明 |
|------|------|------|
| `with_structured_output(M)` 默认 | ❌ 400 `This response_format type is unavailable now` | 默认走 `json_schema`，DeepSeek 不支持 |
| `with_structured_output(M, method="function_calling")` | ❌ 400 `Thinking mode does not support this tool_choice` | 思考模型不支持**强制** tool_choice |
| `with_structured_output(M, method="json_mode")` | ⚠️ 能出 JSON，但**字段名自己编** | 它只保证是 JSON，不保证符合 Schema |
| `with_structured_output(M, method="json_mode")` + 提示词里明确列出字段 | ✅ 可用 | 需要你自己把字段要求写进 prompt |
| `PydanticOutputParser` + 提示词 | ✅ **推荐** | Schema 由 `get_format_instructions()` 自动注入 |
| `JsonOutputParser` + 提示词 | ✅ 可用 | 不校验类型，拿到 dict |
| `llm.bind_tools([...])`（不强制 tool_choice） | ✅ 正常 | 这才是能用的工具调用姿势（阶段 2 的老朋友） |

**结论**：框架的"一行搞定"在国产/兼容端点上经常不灵。**先手写后框架**这条路线的价值就在这里——你知道它内部要发什么请求，所以一眼能看出该换哪种 method。

### 完整代码：`01_langchain_basics.py`

```python
"""阶段 7 第 1 课:LangChain 1.x 基础——提示词模板 / 模型接入 / 输出解析"""
import os

from dotenv import load_dotenv
from langchain_core.messages import AIMessage, HumanMessage
from langchain_core.output_parsers import JsonOutputParser, PydanticOutputParser, StrOutputParser
from langchain_core.prompts import (
    ChatPromptTemplate,
    FewShotChatMessagePromptTemplate,
    MessagesPlaceholder,
)
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field

load_dotenv()

llm = ChatOpenAI(
    model=os.environ["MODEL_NAME"],
    api_key=os.environ["OPENAI_API_KEY"],
    base_url=os.environ["OPENAI_BASE_URL"],
    temperature=0.3,
)

print("=" * 60)
print("1. 提示词模板 + 管道(LCEL):模板 | 模型 | 解析器")
print("=" * 60)
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是{role},回答不超过 {limit} 个字。"),
    ("human", "{question}"),
])
chain = prompt | llm | StrOutputParser()
print(chain.invoke({"role": "Python 老师", "limit": 40, "question": "什么是装饰器?"}))

print("\n" + "=" * 60)
print("2. Few-shot 模板:用例子教模型输出格式")
print("=" * 60)
examples = [
    {"input": "这个产品太棒了", "output": "正面"},
    {"input": "客服半天不回消息", "output": "负面"},
]
example_prompt = ChatPromptTemplate.from_messages([("human", "{input}"), ("ai", "{output}")])
few_shot = FewShotChatMessagePromptTemplate(example_prompt=example_prompt, examples=examples)
few_shot_chain = ChatPromptTemplate.from_messages([
    ("system", "判断情感倾向,只输出 正面/负面/中性 之一,不要解释。"),
    few_shot,
    ("human", "{input}"),
]) | llm | StrOutputParser()
print("输入:包装破了,但东西还能用 ->", few_shot_chain.invoke({"input": "包装破了,但东西还能用"}))

print("\n" + "=" * 60)
print("3. 上下文模板:MessagesPlaceholder 插历史(对照阶段 1 手写的 messages)")
print("=" * 60)
ctx_chain = ChatPromptTemplate.from_messages([
    ("system", "你是简洁的助手。"),
    MessagesPlaceholder("history"),
    ("human", "{question}"),
]) | llm | StrOutputParser()
history = [HumanMessage("我叫小王,是 Java 后端"), AIMessage("你好小王,记住了。")]
print(ctx_chain.invoke({"history": history, "question": "我叫什么?做什么的?"}))


print("\n" + "=" * 60)
print("4. 结构化输出:三种写法的实测对比")
print("=" * 60)


class Job(BaseModel):
    """招聘信息结构化抽取"""

    title: str = Field(description="岗位名称")
    city: str = Field(description="工作城市")
    must_have: list[str] = Field(description="硬性要求,最多 3 条")


JD = "上海招高级 Python 后端,3 年以上经验,熟悉 FastAPI 与 MySQL,懂 RAG 加分"

# 写法 A(★推荐):PydanticOutputParser 把 JSON Schema 写进提示词,失败自己重试
parser = PydanticOutputParser(pydantic_object=Job)
job_a = (ChatPromptTemplate.from_messages([
    ("system", "从招聘信息里抽取字段。\n{format}"),
    ("human", "{text}"),
]).partial(format=parser.get_format_instructions()) | llm | parser).invoke({"text": JD})
print("写法A PydanticOutputParser ->", job_a.model_dump())

# 写法 B:JsonOutputParser(不校验类型,但能拿到 dict)
jparser = JsonOutputParser(pydantic_object=Job)
job_b = (ChatPromptTemplate.from_messages([
    ("system", "抽取字段,输出 json。\n{format}"),
    ("human", "{text}"),
]).partial(format=jparser.get_format_instructions()) | llm | jparser).invoke({"text": JD})
print("写法B JsonOutputParser     ->", job_b)

# 写法 C(❌踩坑演示):with_structured_output 的默认行为,DeepSeek 上会 400
try:
    job_c = llm.with_structured_output(Job).invoke(f"从这段招聘信息抽取字段:{JD}")
    print("写法C with_structured_output ->", job_c.model_dump())

    f"招聘信息:{JD}"

print("5. 工具绑定(不强制 tool_choice 时才安全)")

## 第 2 课 · 记忆管理:滑动窗口 / 长会话摘要 / 会话隔离（90 分钟）

> 对应 PDF 3.c「大模型记忆管理代码实操(包括滑动窗口、长会话摘要等)」。
> 阶段 3 第 6 课你已经手写过一遍(按轮裁剪 + 摘要混合),本课用框架重做,并补上**多会话隔离**。

### 目标

1. 亲眼看到"只留最近 N 条"会**丢事实**(这不是理论,是实测)
2. 用**摘要压缩**把被裁掉的旧轮次救回来
3. 用 `RunnableWithMessageHistory` 做**按 session 隔离**的会话记忆(单机 CLI 的 `messages` 升级成多用户服务)
4. 分清三层记忆策略各自的价格和代价

### 核心概念

**① 记忆的本质是"预算分配"**:上下文窗口是有限的,记忆策略就是"哪些内容值得留在窗口里"。所以有三种做法:

| 策略 | 做法 | 省 token | 代价 | 实测表现 |
|---|---|---|---|---|
| 全量 | 全塞进去 | ❌ | 迟早撑爆窗口 | 第 1 步:答对(因为还没超) |
| 滑动窗口 | 只留最近 N 轮 | ✅✅ | **早期事实永久丢失** | 第 2 步:答不出工号 |
| 摘要压缩 | 旧轮次压成一段话再带上 | ✅ | 摘要本身的 token + 丢细节 | 第 3 步:答对 |
| 长期记忆(mem0) | 事实抽出来存库,按需召回 | ✅✅✅ | 要维护向量库(第 9 课) | 跨会话也记得 |

**② 按"条"裁是阶段 3 踩过的坑**:工具调用会产生 `assistant(tool_calls)` + `tool` 两条消息,裁一半 = 请求 400。所以要么按"轮"裁(阶段 3 手写版),要么交给框架的消息结构管理。

**③ `RunnableWithMessageHistory` = 阶段 4 的 `messages` 列表 + `session_id` 分桶**

```python
RunnableWithMessageHistory(chain, lambda session_id: 取该会话历史, input_messages_key="question", history_messages_key="history")
# 阶段 4:一个全局 messages 列表(单用户 CLI 够用)
# 现在:每个 session_id 一个历史桶(多用户服务必须)
```

## 第 3 课 · Native RAG:切块 → 向量库 → 检索问答（120 分钟）

> 对应 PDF 3.d「Native RAG(这块是面试重点,但是也是基础),这里需要写一个简单的项目」。
> 阶段 3 你手写过向量库和余弦相似度;本课用 LangChain 重做,重点是**对照**。

### 目标

1. 用 `RecursiveCharacterTextSplitter` 切块,并解释它和你手写切块策略的差异
2. 用 `InMemoryVectorStore` + `OpenAIEmbeddings` 完成离线建库
3. 完成在线检索问答,**回答带来源引用**
4. 说清"Native RAG"的边界(什么时候不够用 → 第 4 课 GraphRAG)

### 核心概念

**① 切块:框架的"递归切" vs 你手写的"按段切"**

| 方案 | 策略 | 同一份语料实测 |
|------|------|----------------|
| 阶段 3 手写 `chunk_text` | 按空行分段,超长才滑窗 | 25 块 |
| `RecursiveCharacterTextSplitter(300, 50)` | 按 `\n\n → \n → 。 → 空格` 递归找切点,再把小块**合并**到接近 300 字 | 10 块 |

块少 = 省 token、上下文更连贯;块多 = 检索更精准。**没有标准答案,要用评测集(附录 C)定**。

**② 离线 / 在线两条流程(PDF 要求的"Native RAG 详细流程")**

```
离线:文档 → 切块 → embedding → 向量库(可持久化)
在线:问题 → embedding → 相似度检索 top-k → 拼进 prompt → 模型回答 + 来源标注
```

**③ `check_embedding_ctx_length=False` 是国内兼容端点的生死开关**
LangChain 默认先按 OpenAI 的私有约定用 tiktoken 把文本切成 token 数组再发请求;硅基流动/智谱这类兼容端点只接受**字符串**。不关掉它,轻则报错,重则结果错乱。

**④ Native RAG 的三个天花板**(引出第 4 课)
1. 只做"像不像"的匹配,不会推理多跳关系
2. 检索质量高度依赖切块与 embedding,调参靠评测
3. 只能回答"资料里写了什么",回答不了"资料整体讲了什么"

"""阶段 7 第 3 课(PDF 3.d):Native RAG 项目——离线建库 + 在线检索问答

离线:文档 → 递归切块 → 向量化 → 存入向量库
在线:问题 → 向量检索 top-k → 拼进 prompt → 回答带来源
"""
import glob
import os

from dotenv import load_dotenv
from langchain_core.documents import Document
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_text_splitters import RecursiveCharacterTextSplitter

load_dotenv()
llm = ChatOpenAI(model=os.environ["MODEL_NAME"], api_key=os.environ["OPENAI_API_KEY"],
                 base_url=os.environ["OPENAI_BASE_URL"], temperature=0.2)
embeddings = OpenAIEmbeddings(
    model=os.environ["EMBEDDING_MODEL"],
    api_key=os.environ["EMBEDDING_API_KEY"],
    base_url=os.environ["EMBEDDING_BASE_URL"],
    check_embedding_ctx_length=False,     # ★ 国内兼容端点必须关掉,否则会走 tiktoken 切 token
)

print("=" * 60)
print("【离线】1. 切块:RecursiveCharacterTextSplitter(对照阶段 3 手写的 chunk_by_size)")
print("=" * 60)
splitter = RecursiveCharacterTextSplitter(
    chunk_size=300,        # 目标长度
    chunk_overlap=50,      # 重叠,防止句子被切断丢语义
    separators=["\n\n", "\n", "。", "!", "?", " ", ""],   # ★ 按优先级递归找切点
)
docs = []
for path in sorted(glob.glob("knowledge/*.txt")):
    text = open(path, encoding="utf-8").read()
    for chunk in splitter.split_text(text):
        docs.append(Document(page_content=chunk, metadata={"source": os.path.basename(path)}))
print(f"切出 {len(docs)} 块;示例:\n  {docs[0].page_content[:80]}...\n  metadata={docs[0].metadata}")

print("\n" + "=" * 60)
print("【离线】2. 向量化入库:InMemoryVectorStore(对照阶段 3 手写的 SimpleVectorStore)")
print("=" * 60)
store = InMemoryVectorStore(embeddings)
store.add_documents(docs)
print("已入库:", len(docs), "块")
for doc, score in store.similarity_search_with_score("年假最多能攒多少天", k=2):
    print(f"  [{score:.4f}] {doc.metadata['source']} | {doc.page_content[:50]}...")

print("\n" + "=" * 60)
print("【在线】3. 检索问答(带来源引用)")

    ("human", "{question}"),
])


def rag_answer(question: str) -> str:
    hits = store.similarity_search(question, k=3)
    context = "\n\n".join(f"[{d.metadata['source']}] {d.page_content}" for d in hits)
    return (rag_prompt | llm | StrOutputParser()).invoke({"context": context, "question": question})


for q in ["年假最多能攒多少天?", "报销单笔超过多少钱需要审批?"]:
    print(f"\n问:{q}\n答:{rag_answer(q)}")

print("4. 下一步:把检索接成一个工具,让模型自己决定查不查(第 5 课的 create_agent)")
print("=" * 60)
for line in [

## 第 4 课 · GraphRAG:向量检索答不了"多跳"（90 分钟）

> 对应 PDF 3.e「Graph RAG(图 RAG,解决 Native RAG 的一些痛点)」。

### 目标

1. 用一个**多跳问题**现场证明向量检索的短板(不是听别人说,是自己跑出来)
2. 手写"三元组 + 多跳遍历",理解 GraphRAG 的最小骨架
3. 说清 GraphRAG 的适用边界与成本,知道什么时候**不该**上

### 核心概念

**① 向量检索衡量的是"像不像",不是"能不能推出来"**

问题:"星链工作台的负责人所在部门的主管是谁?" 需要把三条事实串起来:

```
星链工作台 --负责人--> 张伟 --所属部门--> 研发中心 --主管--> 李强
```

这三条事实分散在三个文档块里,`similarity_search` 只能返回"最像的 k 块"——实测 top2 命中"系统清单""人员分工",**缺"组织架构"那一块**,所以无论怎么拼 prompt 都推不出答案。

**② GraphRAG 的骨架**:先把文档抽成"实体-关系"(三元组),再沿边做多跳游走。

```python
TRIPLES = [("星链工作台", "负责人", "张伟"), ("张伟", "所属部门", "研发中心"), ("研发中心", "主管", "李强")]
walk("星链工作台", ["负责人", "所属部门", "主管"])   # → 李强
```

生产里第一步(抽三元组)由 LLM 逐篇完成,存在 Neo4j / NebulaGraph 这类图库里;检索时是"图遍历 + 向量检索"混合。

**③ 什么时候值得上(这张表比概念重要)**

| 场景 | 建议 |
|---|---|
| 单跳事实问答(年假多少天) | ❌ 用向量 RAG,便宜又准 |
| 跨文档多跳("A 的负责人的上级") | ✅ 考虑 GraphRAG |
| 全局摘要("这批文档讲了几个主题") | ✅ 图 + 社区摘要更强 |
| 文档天天变 | ⚠️ 图更新成本高,谨慎 |

    """从 start 出发,按给定关系链一路走下去,返回 (终点, 路径)"""
    node, path = start, [start]

        if nxt is None:
            return None, " -> ".join(path) + f" (缺少关系 {rel})"
        node = nxt
        path.append(node)
    return node, " -> ".join(path)

## 第 5 课 · Agent 与 Function Call 全流程（120 分钟）

> 对应 PDF 3.f「Agent(如何给 LLM 提供工具、Agent 如何调用工具,全流程)」+ 3.g「Function Call 函数调用」。
> 阶段 2 你手写了整个循环,本课看框架把它压成了什么,以及**框架没帮你做的那部分**。

### 目标

1. 用 `create_agent` 一行搭出带工具的 Agent,并看到完整的"点菜 → 执行 → 喂回"轨迹
2. 逐条对照阶段 2 手写版:框架替你做了哪四件事
3. 说清**框架没做**的三件事(白名单/预算/输出规格),它们由第 10、13 课补齐

### 核心概念

**① 一行 vs 四十行**

```python
# 阶段 2 你手写的:for 循环 + tool_calls 判断 + TOOL_IMPLS 调度 + role=tool 喂回
agent = create_agent(llm, tools=TOOLS, system_prompt="...")   # 框架版
result = agent.invoke({"messages": [HumanMessage("北京天气怎么样?")]})
```

**② 工具定义没变**——还是阶段 4 那一套:`@tool` 装饰器 + docstring 当 description + 类型注解变 JSON Schema。**你手写过的注册器,就是框架内部的那个东西。**

**③ 框架替你做的四件事**

| 环节 | 手写版 | 框架版 |
|---|---|---|
| Schema 生成 | 手写 JSON Schema(阶段 2)或装饰器反射(阶段 4) | `@tool` 反射 |
| 循环控制 | `for _ in range(MAX_STEPS)` + `if not msg.tool_calls` | `create_agent` 内部的图循环 |
| 工具执行 + 异常 | `try/except` 兜底成字符串 | `ToolNode` 捕获后作为 `ToolMessage` 回传 |
| 消息历史 | 自己 `history.append({...})` | LangGraph state + `add_messages` reducer |

**④ 框架没替你做的三件事(重点)**

1. **工具白名单**:你传给 `tools=` 的每一个工具,模型都能调。危险工具别放进去(第 10 课 harness 还有一层名单校验)。
2. **预算与步数**:框架不设上限,模型可以一直调工具直到窗口爆炸(第 10 课)。
3. **业务输出规格**:框架不校验你的业务字段是否合规(第 13 课 SDD)。

> 一句话总结:**框架省的是"管道工"的活,不是"架构师"的活。**

## 第 6 课 · 把 MCP 工具接进 Agent（120 分钟）

> 对应 PDF 3.h「MCP(包括是什么,实操 & 原理)」。阶段 5 你已经手写过 MCP server/client,本课解决最后一公里:
> **跨进程的工具,怎么变成 Agent 手里的工具。**

### 目标

1. 复用阶段 5 的 `MCPToolbox`(同步桥)把 MCP server 连起来
2. 写一个 30 行的适配层:把 MCP 的 `input_schema` 变成 Pydantic 模型 → LangChain 工具
3. 跑通"LangChain Agent 点菜 → MCP 跨进程执行 → 结果喂回"的完整链路
4. 说清三层分工(server / toolbox / 适配层)

### 核心概念

**① 为什么需要适配层**:MCP 给你的是 **JSON Schema**(协议层),LangChain 要的是 **BaseTool**(框架层)。中间这一步就是"接口适配"——Java 视角:两个 SDK 之间的 Adapter。

**② 从 JSON Schema 动态造 Pydantic 模型**

```python
JSON2PY = {"string": str, "integer": int, "number": float, "boolean": bool}
fields = {name: (JSON2PY.get(spec["type"], str), ... if name in required else None) for ...}
args_schema = create_model(f"{tool}_Args", **fields)
```
没有字段的工具也要给一个**空的** Pydantic 模型,否则 LangChain 会把 `**kwargs` 推断成一个叫 `kwargs` 的参数(实测踩过)。

**③ 三层分工**

| 层 | 谁 | 职责 |
|---|---|---|
| MCP server(`file_server.py`) | 阶段 5 | 工具实现,独立进程,任何 MCP 客户端都能连 |
| `MCPToolbox`(`mcp_client.py`) | 阶段 5 | 同步桥 + 会话管理 + 跨进程调用 |
| 适配层(本课) | 本课 | JSON Schema → Pydantic → `BaseTool` |

**④ ★ 一个真实的依赖坑(实测)**:`pip install langchain-mcp-adapters` 会把 `mcp` 从 2.x **降级到 1.x**,而阶段 5 的 `from mcp.server.mcpserver import MCPServer` 在 1.x 里不存在 → 第 5 章直接报 `ModuleNotFoundError`。本课因此**不用那个官方适配包**,改用你阶段 5 手写的 toolbox 自己桥接。教训:**装包前先看它会动哪些依赖**(`pip install --dry-run`)。

### 完整代码：`06_mcp_agent.py`

"""阶段 7 第 6 课:把 MCP 工具接进 LangChain Agent

桥接思路:阶段 5 手写的 MCPToolbox(同步桥)负责跨进程说话,
          LangChain 只认 BaseTool —— 中间加一层"JSON Schema → Pydantic 模型"的适配。
"""
import os
import sys

from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain_core.tools import StructuredTool
from langchain_openai import ChatOpenAI
from mcp import StdioServerParameters
from pydantic import create_model

from mcp_client import MCPToolbox          # ← 从 05_mcp 拷过来的阶段 5 成果

load_dotenv()
llm = ChatOpenAI(model=os.environ["MODEL_NAME"], api_key=os.environ["OPENAI_API_KEY"],
                 base_url=os.environ["OPENAI_BASE_URL"], temperature=0)

SERVERS = {
    "file": StdioServerParameters(command=sys.executable, args=["file_server.py"]),
}

JSON2PY = {"string": str, "integer": int, "number": float, "boolean": bool}


def mcp_tool_to_langchain(box: MCPToolbox, public_name: str) -> StructuredTool:
    """MCP 的 input_schema → Pydantic 模型 → LangChain 工具"""
    _, real_name, tool = box._tools[public_name]
    schema = tool.input_schema or {}
    fields = {}
    for fname, spec in schema.get("properties", {}).items():
        py_type = JSON2PY.get(spec.get("type"), str)
        required = fname in schema.get("required", [])
        fields[fname] = (py_type, ... if required else None)
    # 即使没有字段也要给一个空模型,否则 LangChain 会把 **kwargs 推断成一个叫 kwargs 的参数
    args_schema = create_model(f"{real_name}_Args", **fields)

    def _run(**kwargs):
        return box.call_tool(public_name, kwargs)

    return StructuredTool.from_function(
        func=_run, name=public_name, description=tool.description or "", args_schema=args_schema
    )


def main():
    with MCPToolbox(SERVERS) as box:
        tools = [mcp_tool_to_langchain(box, n) for n in box.tool_names()]
        print("=" * 60)
        print("1. MCP 工具 → LangChain 工具(零硬编码)")
        print("=" * 60)
        for t in tools:
            print(f"  {t.name} | args={list((t.args_schema.model_fields if t.args_schema else {}))}"
                  f" | {t.description[:30]}")

        agent = create_agent(
            llm, tools=tools,
            system_prompt="你是助手。需要时间或文件操作时必须调用工具,不要凭记忆编造。",
        )

        print("\n" + "=" * 60)
        print("2. 跑一轮:Agent 从 LangChain 出发,工具在另一个进程里执行")
        print("=" * 60)
        result = agent.invoke({"messages": [
            {"role": "user", "content": "现在几点?把时间写进 mcp_note.txt,再把内容读回来确认。"}
        ]})
        for msg in result["messages"]:
            for tc in (getattr(msg, "tool_calls", None) or []):
                print(f"  [点菜] {tc['name']}({tc['args']})")
            if msg.__class__.__name__ == "ToolMessage":
                print(f"  [喂回] {str(msg.content)[:60]}")
        print("-" * 60)

## 第 7 课 · Agent SKILLS:渐进式披露（PDF 3.i）

> 对照《Agent 开发完整学习路线》第 3 章 i：掌握概念、编写方法、使用流程及背后原理。
> 原文一句话：**"这块目前是开发范式，在公司工作流基本都是写 SKILLS。"**

### 目标

1. 说清 SKILL 和「工具」「MCP」「系统提示词」的分工
2. 写两个企业味儿的 `SKILL.md`（周报规范、代码评审规范）
3. 用 60 行实现一个技能加载器：**第一层只加载名字+描述，第二层按需加载正文，第三层按需读附件**
4. 实测"有技能 / 没技能"的回答差异，以及省下的上下文比例

### 核心概念

**① SKILL 是什么？** 一份 markdown 格式的**作业规范**：前几行是元数据（名字 + 什么时候用），正文是"这类活该怎么干"（步骤、模板、检查清单）。它和工具的本质区别：

| 机制 | 载体 | 谁决定使用 | 内容量级 | 你学过的地方 |
|------|------|-----------|---------|-------------|
| 系统提示词 | prompt 字符串 | 开发者（永远在场） | 必须很小 | 阶段 3 的硬规则 |
| **工具** | 函数 | **模型**决定调用 | 执行动作 | 阶段 2/4 |
| **MCP** | 跨进程协议 | 模型决定调用（远端） | 执行动作 + 数据 | 阶段 5 |
| **SKILL** | markdown 文档 | 模型决定**加载** | 大段**知识/规范** | 本课 |
| resource | MCP 原语 | 应用/用户读 | 只读数据 | 阶段 5 第 4 课 |

**② 渐进式披露（progressive disclosure）= 三层加载**

```
第一层:启动时只把 name + description 塞进 system prompt   ← 每个技能 ~60 字
第二层:模型判断要用 → 调用 load_skill(name) 拿回完整正文   ← 几百到几千字
第三层:正文里提到附件 → 调用 read_skill_file() 按需读      ← 用到才读
```

**③ 为什么企业爱用它？** 因为规范是**人写的、会长大的**：新政策来了改 markdown，不用改代码、不用重新部署；而且**只有被用到的技能才占用 token**——实测两个技能就省 78% 上下文，20 个技能时省得更多（对比"把所有规范塞进 system prompt"的写法，那是每轮都付费）。

**④ 和 MCP 组合**：SKILL 告诉模型"怎么干"，MCP 提供"用什么干"。生产里常见形态：SKILL.md 里写"评审代码时先查 `kb__search_knowledge` 里的《研发规范》，再按四步输出"。

"""阶段 7 第 7 课:Agent SKILLS——渐进式披露(progressive disclosure)

核心:技能正文不进 system prompt,只进"名字 + 一句话描述"(第一层);
模型判断需要时才调用 load_skill 把正文拿进来(第二层);

import os
import re
from pathlib import Path

from dotenv import load_dotenv
from langchain.agents import create_agent
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI

load_dotenv()
SKILLS_DIR = Path(__file__).parent / "skills"

                 base_url=os.environ["OPENAI_BASE_URL"], temperature=0.2)

FRONT_MATTER = re.compile(r"^---\s*\n(.*?)\n---\s*\n(.*)$", re.S)


def parse_skill(path: Path) -> dict:
    """解析 SKILL.md:YAML front matter 只认 name/description,正文是 markdown"""
    raw = path.read_text(encoding="utf-8")
    m = FRONT_MATTER.match(raw)
    if not m:
        raise ValueError(f"{path} 缺少 front matter(--- name/description ---)")
    head, body = m.group(1), m.group(2)
    meta = dict(re.findall(r"^(\w+):\s*(.+)$", head, re.M))
    return {"name": meta["name"], "description": meta["description"], "body": body.strip(),
            "dir": path.parent}


# ---------- 第一层:只扫描"名字 + 描述",正文一个字符都不进上下文 ----------
CATALOG = {}
for skill_file in sorted(SKILLS_DIR.glob("*/SKILL.md")):

    CATALOG[info["name"]] = info

body_chars = sum(len(s["body"]) for s in CATALOG.values())
print("=" * 60)
print("1. 技能目录(只加载这一层)")
print("=" * 60)
print(catalog_text)

      f"  → 省掉约 {body_chars / (len(catalog_text) + body_chars):.0%} 的上下文")


# ---------- 第二/三层:做成工具,让模型自己决定何时加载 ----------
@tool
def load_skill(name: str) -> str:
    """加载指定技能的完整正文(规范/步骤/模板)。需要按公司规范干活时先调用它。"""
    info = CATALOG.get(name)
    if info is None:
        return f"没有名为 {name} 的技能。可用技能:{', '.join(CATALOG)}"
    print(f"  >> 模型加载了技能正文:{name}")
    return info["body"]


@tool
def read_skill_file(name: str, filename: str) -> str:
    """读取技能目录里的附件(模板、示例、清单)。"""
    info = CATALOG.get(name)
    if info is None:
        return f"没有名为 {name} 的技能"
    target = (info["dir"] / filename).resolve()
    if not str(target).startswith(str(info["dir"].resolve())):
        return "拒绝:不允许读取技能目录之外的文件"     # ★ 路径穿越防护
    if not target.exists():
        return f"技能 {name} 下没有文件 {filename}"
    return target.read_text(encoding="utf-8")


SYSTEM = (
    "你是研发助理。下面是可用技能清单,需要按公司规范做事时,先调用 load_skill 加载对应技能,"

        "周四开始做评测集,目前完成 60%;下周准备接 Milvus。")

for msg in result["messages"]:
    for tc in (getattr(msg, "tool_calls", None) or []):
        print(f"  [工具调用] {tc['name']}({tc['args']})")
print("-" * 60)
print(result["messages"][-1].content)

print("\n" + "=" * 60)
print("3. 对照:没有技能目录时,同一个任务(模型自己发挥)")
print("=" * 60)
plain = create_agent(llm, tools=[], system_prompt="你是研发助理,帮用户把工作记录整理成周报。")
print(plain.invoke({"messages": [{"role": "user", "content": task}]})["messages"][-1].content[:400])

## 第 8 课 · LangGraph:状态图 / Checkpoint / HITL（PDF 3.j）

> 对照《Agent 开发完整学习路线》第 3 章 j：节点、状态、边、条件边、Checkpoint 持久化、Human-in-the-Loop、多 Agent 基础、上下文管理。

### 目标

1. 用 `StateGraph` 把 Agent 写成**图**：状态（State）+ 节点（Node）+ 边（Edge）
2. 用**条件边**做分支（该自动回复还是转人工？）
3. 用 `InMemorySaver` / `SqliteSaver` 做 **Checkpoint**：按 `thread_id` 记住会话，进程重启也不丢
4. 用 `interrupt()` + `Command(resume=...)` 做 **Human-in-the-Loop**（人工审批后才继续）

### 核心概念

**① 为什么需要图？** 阶段 6 你手写的 orchestrator 是"主管调工人"，是**一次性**的流程；LangGraph 解决的是**有状态、可循环、可中断、可恢复**的流程——客服升级、审批流、多轮工具循环都属于这类。

**② State 是"共享内存"，reducer 决定怎么合并**

```python
class State(TypedDict):
    messages: Annotated[list, add_messages]   # ★ add_messages = 追加而不是覆盖
    need_human: bool                          # 默认行为:新值覆盖旧值
```
`Annotated[list, add_messages]` 就是阶段 2 里你手动 `history.append(...)` 的声明式版；忘了写 reducer，历史会被**整个覆盖**（这是新手最常踩的坑）。

**③ 节点 = 收 state、返回"要改的字段"的纯函数**

```python
def classify(state) -> dict:
    return {"need_human": True}     # 只返回增量,不用管其他字段
```

**④ 条件边 = 阶段 6 的 router**

```python
g.add_conditional_edges("classify", route, {"answer": "answer", "escalate": "escalate"})
# route(state) 返回字符串,决定下一站
```

**⑤ Checkpoint：`thread_id` 就是会话 ID**

```python
app = graph.compile(checkpointer=InMemorySaver())
app.invoke(input, {"configurable": {"thread_id": "user-A"}})   # 同一个 thread 自动带上历史
```
换 `thread_id` = 换会话；`SqliteSaver` 落盘后**进程重启仍能接着聊**（实测：关掉连接重开，模型仍记得订单号 A12345）。

**⑥ Human-in-the-Loop：`interrupt()` 暂停，`Command(resume=...)` 继续**

```python
decision = interrupt({"问题": "要不要退款?"})     # 图在这里停下,把问题抛给人工
...
app.invoke(Command(resume="同意退款,补偿 20 元券"), config)   # 人工输入后继续
```
暂停时可以检查 `result["__interrupt__"]` 拿到待审内容，`app.get_state(config).next` 看到停在哪。

> **★ 实测踩坑**：恢复时，被中断的节点会**从头重新执行**（实测 `[escalate]` 打印了两次）。所以 `interrupt()` **之前**不要放有副作用的代码（发消息、扣款、写库）——要放就放在 `interrupt()` 之后。这是 LangGraph 最经典的坑。

### 完整代码：`08_langgraph.py`

```python
"""阶段 7 第 8 课:LangGraph——状态图 / 条件边 / Checkpoint / Human-in-the-Loop"""
import os
import sqlite3
from typing import Annotated, TypedDict

from dotenv import load_dotenv
from langchain_core.messages import HumanMessage, SystemMessage
from langchain_openai import ChatOpenAI
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.graph import END, START, StateGraph
from langgraph.graph.message import add_messages
from langgraph.types import Command, interrupt

load_dotenv()
llm = ChatOpenAI(model=os.environ["MODEL_NAME"], api_key=os.environ["OPENAI_API_KEY"],
                 base_url=os.environ["OPENAI_BASE_URL"], temperature=0.2)


# ---------- 状态:图里流转的"共享内存" ----------
class State(TypedDict):
    # Annotated[..., add_messages] 叫 reducer:新消息追加,而不是覆盖
    messages: Annotated[list, add_messages]
    need_human: bool


# ---------- 节点:每个节点就是一个函数,收 state 返回"要更新的字段" ----------
def classify(state: State) -> dict:
    """判断是否需要人工介入(演示用:出现"退款/投诉"就升级)"""
    last = state["messages"][-1].content
    need = any(kw in last for kw in ("退款", "投诉", "起诉"))
    print(f"  [classify] 用户说:{last[:30]}… -> 需要人工={need}")
    return {"need_human": need}


def answer(state: State) -> dict:
    print("  [answer] 走自动回复分支")
    reply = llm.invoke([SystemMessage("你是电商客服,一句话回答。")] + state["messages"])
    return {"messages": [reply]}


def escalate(state: State) -> dict:
    print("  [escalate] 走人工分支,等人确认再回复")
    decision = interrupt({"问题": "要不要退款?", "用户原话": state["messages"][-1].content})
    print(f"  [escalate] 人工回复:{decision}")
    return {"messages": [SystemMessage(f"客服主管决定:{decision}")]}


def route(state: State) -> str:
    """条件边:返回下一个节点的名字"""
    return "escalate" if state["need_human"] else "answer"


def build_graph(checkpointer=None):
    g = StateGraph(State)
    g.add_node("classify", classify)
    g.add_node("answer", answer)
    g.add_node("escalate", escalate)
    g.add_edge(START, "classify")
    g.add_conditional_edges("classify", route, {"answer": "answer", "escalate": "escalate"})
    g.add_edge("answer", END)
    g.add_edge("escalate", END)
    return g.compile(checkpointer=checkpointer)


print("=" * 60)
print("1. 状态图 + 条件边(自动回复分支)")

## 第 9 课 · mem0 长期记忆（PDF 4.1）

### 目标

用 mem0 实现**跨会话记忆**：用户说"我喜欢喝咖啡"，下次对话 Agent 能记住并推荐咖啡店——而不是只靠 messages 列表（重启就丢）。

### 核心概念

**mem0 = 向量检索 + 时间衰减 + 自动去重**

- **User memory**：长期记忆，绑定用户 ID（如"user_123 喜欢咖啡"）
- **Session memory**：短期记忆，绑定会话 ID（如"这次对话在聊旅行"）
- **自动提取**：Agent 对话中提到的偏好、事实，mem0 自动存储
- **时间衰减**：旧记忆权重降低，最近的更重要

对比阶段 3 的 RAG：
- RAG 存"知识文档"（公司规章、技术手册），静态内容
- mem0 存"用户画像"（喜好、历史交互），动态更新

"""
mem0 长期记忆示例
场景：用户多次对话，Agent 记住用户偏好
"""
import os
from dotenv import load_dotenv
from openai import OpenAI
from mem0 import Memory

load_dotenv()

# ---- 配置 ----
client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL")
)
MODEL = os.environ.get("MODEL_NAME")

# ---- 初始化 mem0（本地 SQLite 模式）----
# 生产环境可以用云端版（需要 MEM0_API_KEY）或接 Qdrant/Milvus
config = {
    "vector_store": {
        "provider": "chroma",
        "config": {
            "collection_name": "user_memories",
            "path": "./mem0_db"
        }
    }
}

memory = Memory.from_config(config)

USER_ID = "user_123"  # 模拟用户 ID

# ---- Agent 对话函数（带记忆）----
def chat_with_memory(user_input: str, user_id: str) -> str:
    """
    1. 检索相关记忆
    2. 拼接到 prompt
    3. 模型回复
    4. 自动提取新记忆存入 mem0
    """
    # 1. 检索相关记忆（top-3）
    relevant_memories = memory.search(user_input, user_id=user_id, limit=3)
    memory_context = "\n".join([m['text'] for m in relevant_memories]) if relevant_memories else "无相关记忆"
    
    # 2. 拼接 prompt
    system_prompt = f"""你是一个助手。以下是用户的历史记忆：

{memory_context}

基于这些记忆个性化你的回答。"""
    
    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_input}
    ]
    
    # 3. 模型回复
    response = client.chat.completions.create(
        model=MODEL,
        messages=messages
    )
    
    assistant_reply = response.choices[0].message.content
    
    # 4. 自动提取记忆（mem0 会分析对话，提取值得记住的信息）
    memory.add(user_input, user_id=user_id, metadata={"source": "user"})
    memory.add(assistant_reply, user_id=user_id, metadata={"source": "assistant"})
    
    print(f"[检索到的记忆] {len(relevant_memories)} 条")
    for m in relevant_memories:
        print(f"  - {m['text'][:50]}...")
    
    return assistant_reply

# ---- 模拟多轮对话 ----
if __name__ == "__main__":
    print("=== 第 1 次对话（初次见面）===")
    reply1 = chat_with_memory("我最近在学 Python，特别喜欢写 Agent。", USER_ID)
    print(f"AI: {reply1}\n")
    
    print("=== 第 2 次对话（建立偏好）===")
    reply2 = chat_with_memory("我不太喜欢 Java，觉得太啰嗦了。", USER_ID)
    print(f"AI: {reply2}\n")
    
    print("=== 第 3 次对话（测试记忆）===")
    reply3 = chat_with_memory("你能推荐一门适合我的编程语言吗？", USER_ID)
    print(f"AI: {reply3}\n")
    # 预期：Agent 会记得"喜欢 Python、不喜欢 Java"，推荐 Python 相关
    
    print("=== 第 4 次对话（跨会话记忆）===")
    # 模拟程序重启，USER_ID 不变
    reply4 = chat_with_memory("我上次跟你聊了什么？", USER_ID)
    print(f"AI: {reply4}\n")
    # 预期：能回忆起之前的对话（Python / Agent）
    
    # ---- 查看所有记忆 ----

    all_memories = memory.get_all(user_id=USER_ID)
    for i, m in enumerate(all_memories, 1):
        print(f"{i}. {m['text'][:80]}... (创建时间: {m.get('created_at', 'N/A')})")
    
    # ---- 实验：删除记忆 ----

## 第 10 课 · harness:五道护栏（PDF 4.2）

> 对应 PDF 4.2「harness(用来约束模型,让模型稳定运行)」。
> DeepSeek Harness 见第 11 课,SDD 见第 13 课,Vibe Coding 见第 14 课。

### 目标

1. 理解 **harness（约束层）** 是什么，为什么"模型是概率系统"就必须有它
2. 手写一个 150 行的 mini-harness，把五道护栏做出来并**逐条验证**
3. 把审计日志落成 JSONL,让"出了什么事"事后可查
4. 知道框架(`create_agent`)没替你做的三件事,分别由本课和第 13 课补上

### 核心概念

**① harness 是什么？**

harness = 套在模型外面的**约束层与执行环境**：模型只能在你划定的范围内行动，越界就被拦下，出错就按预案降级。类比 Java：模型是"不受信任的第三方 SDK"，harness 是你写的**网关 + 熔断 + 审计**。

它的价值在阶段 6/7 变得非常具体：一个有 2 个 MCP server、20 个工具的 Agent，如果不管：
- 它会调用你没授权的工具（**越权**）
- 它会陷进死循环（**烧钱**）
- 它会把 30 秒的工具调用挂成"卡死"（**雪崩**）
- 它会返回格式不对的结果，把下游接口搞崩（**脏数据**）
- 出了问题你没日志可查（**不可观测**）

**② 五道护栏（本课全部实测）**

| 护栏 | 做法 | 实测结果 |
|------|------|---------|
| 工具白名单 | `allowed_tools` 之外的直接拒绝 | 模型调 `delete_all_files` → `拒绝执行:工具 delete_all_files 不在白名单内` |
| 工具超时 | 线程池 `future.result(timeout)` | 工具睡 5s、策略给 1s → `工具 sleep_tool 超时(>1.0s),已中断等待` |
| token 预算 | 累加 `usage_metadata`，超限即停 | 假模型每次报 30000 token → `本轮已达 token 预算上限,请人工接手。` |
| 步数上限 | `MAX_STEPS`（阶段 2 的老朋友） | 无限点菜 → `达到最大步数,已强制停止。` |
| 输出规格校验 | Pydantic + 打回重试 | 缺 `evidence` 字段 → 审计里出现 `schema_retry`，第二次通过 |

### 完整代码：`10_harness.py`

```python
"""阶段 7 第 10 课:harness(模型约束层)+ SDD 规格驱动开发

harness 要解决一个问题:模型是概率系统,你不加约束它就敢删库、敢死循环、敢烧钱。
本课用 150 行做一个 mini-harness:白名单 / 步数 / 超时 / 预算 / 输出校验 / 审计日志 / 降级。
"""
import json
import os
import time
from concurrent.futures import ThreadPoolExecutor, TimeoutError as FutureTimeout
from dataclasses import dataclass, field
from pathlib import Path

from dotenv import load_dotenv
from langchain_core.messages import AIMessage, HumanMessage, SystemMessage, ToolMessage
from langchain_core.tools import tool as lc_tool
from langchain_openai import ChatOpenAI
from pydantic import BaseModel, Field, ValidationError

load_dotenv()
LOG_FILE = Path(__file__).parent / "harness_audit.jsonl"


# ============ 1. 策略:所有约束集中在一处,而不是散落在提示词里 ============
@dataclass
class Policy:
    allowed_tools: tuple[str, ...] = ("calc", "search_kb", "sleep_tool")
    max_steps: int = 5
    tool_timeout_s: float = 2.0
    token_budget: int = 20000
    max_retries: int = 1


class Answer(BaseModel):
    """最终输出的规格(SDD:先定规格,再让 Agent 干活)"""

    conclusion: str = Field(description="结论,一句话")
    evidence: list[str] = Field(description="支撑证据,至少 1 条")
    confidence: float = Field(description="置信度 0-1", ge=0, le=1)


# ============ 2. 工具:用 @tool 装饰器,Schema 由框架反射签名生成(阶段 4 的同一招) ============
@lc_tool
def calc(expression: str) -> str:
    """计算一个纯算术表达式,例如 (12+8)*3"""
    allowed = set("0123456789+-*/(). ")
    if not set(expression) <= allowed:
        raise ValueError("只允许数字和 + - * / ( )")
    return str(eval(expression))          # 已做字符白名单,这里才敢 eval


@lc_tool
def search_kb(query: str) -> str:
    """查询公司知识库(考勤、假期等制度)"""
    return "年假:每年 10 天,满 3 年 +5 天,上限 20 天;最多结转 5 天。"


@lc_tool
def sleep_tool(seconds: float) -> str:
    """故意睡很久,用来演示超时拦截"""
    time.sleep(seconds)
    return f"睡完了 {seconds} 秒"


TOOLS = {t.name: t for t in (calc, search_kb, sleep_tool)}


# ============ 3. harness 本体 ============
class Harness:
    def __init__(self, model_call, tools: dict, system: str, policy: Policy = None):
        self.model_call = model_call          # (messages, tool_specs) -> AIMessage
        self.tools = tools
        self.system = system
        self.policy = policy or Policy()
        self.used_tokens = 0
        self.steps = 0
        self.trace = []

    def _audit(self, **kw):
        kw["ts"] = time.strftime("%H:%M:%S")
        self.trace.append(kw)
        with LOG_FILE.open("a", encoding="utf-8") as f:
            f.write(json.dumps(kw, ensure_ascii=False) + "\n")

    def _run_tool(self, name: str, args: dict) -> str:
        # 护栏 1:白名单——不在名单里的工具,连碰都别想碰
        if name not in self.policy.allowed_tools or name not in self.tools:
            self._audit(event="tool_blocked", tool=name, args=args)
            return f"拒绝执行:工具 {name} 不在白名单内"
        # 护栏 2:超时——模型给个 tools.exec 也能被你拦住
        started = time.time()
        with ThreadPoolExecutor(max_workers=1) as pool:
            try:
                out = pool.submit(self.tools[name].invoke, args).result(timeout=self.policy.tool_timeout_s)
                self._audit(event="tool_ok", tool=name, args=args, cost_s=round(time.time() - started, 2))
                return str(out)
            except FutureTimeout:
                self._audit(event="tool_timeout", tool=name, args=args, limit_s=self.policy.tool_timeout_s)
                return f"工具 {name} 超时(>{self.policy.tool_timeout_s}s),已中断等待"
            except Exception as e:
                self._audit(event="tool_error", tool=name, args=args, error=str(e))
                return f"工具执行出错:{e}"

    def run(self, user_input: str) -> dict:
        messages = [SystemMessage(self.system), HumanMessage(user_input)]
        tool_specs = list(self.tools.values())   # BaseTool 列表,交给 bind_tools

        while self.steps < self.policy.max_steps:
            self.steps += 1
            # 护栏 3:预算——烧到上限立刻停,而不是等账单
            if self.used_tokens > self.policy.token_budget:
                self._audit(event="budget_exceeded", used=self.used_tokens, budget=self.policy.token_budget)
                return {"status": "budget_exceeded", "answer": "本轮已达 token 预算上限,请人工接手。",
                        "trace": self.trace}

            msg = self.model_call(messages, tool_specs)
            usage = getattr(msg, "usage_metadata", None) or {}
            self.used_tokens += usage.get("total_tokens", 0)
            messages.append(msg)

            if not getattr(msg, "tool_calls", None):
                # 护栏 4:输出规格校验 + 重试(SDD 的验收标准)
                answer, err = self._validate(msg.content)
                if answer is not None:
                    self._audit(event="done", steps=self.steps, tokens=self.used_tokens)
                    return {"status": "ok", "answer": answer, "trace": self.trace}
                self._audit(event="schema_retry", error=err)
                messages.append(HumanMessage(
                    f"输出不符合规格:{err}\n请严格按 conclusion/evidence/confidence 三个字段输出 JSON。"))
                continue

            for tc in msg.tool_calls:
                result = self._run_tool(tc["name"], tc["args"])
                messages.append(ToolMessage(result, tool_call_id=tc["id"]))

        self._audit(event="max_steps", steps=self.steps)
        return {"status": "max_steps", "answer": "达到最大步数,已强制停止。", "trace": self.trace}

    def _validate(self, content: str):
        raw = content.strip().removeprefix("```json").removeprefix("```").removesuffix("```").strip()
        try:
            return Answer.model_validate_json(raw), None
        except ValidationError as e:
            return None, f"{e.errors()[0]['loc']} {e.errors()[0]['msg']}"


# ============ 4. 真实模型入口 ============
llm = ChatOpenAI(model=os.environ.get("MODEL_NAME"), api_key=os.environ.get("OPENAI_API_KEY"),
                 base_url=os.environ.get("OPENAI_BASE_URL"), temperature=0)


def real_model_call(messages, tool_specs):
    return llm.bind_tools(tool_specs).invoke(messages)

SYSTEM = ("你是严谨的助理。可以调用工具;最终回答必须是 JSON:"
          '{"conclusion": "...", "evidence": ["..."], "confidence": 0.9}')

print("=" * 60)
print("1. 正常运行:模型调工具 → 输出过规格校验")
print("=" * 60)
h = Harness(real_model_call, TOOLS, SYSTEM)
r = h.run("年假最多能攒多少天?帮我算一下 20 天里如果用掉 13 天还剩几天,用工具算。")
print("status:", r["status"])
print("answer:", r["answer"])
print("tokens:", h.used_tokens, " steps:", h.steps)

print("\n" + "=" * 60)
print("2. 护栏演示(用假模型注入恶意行为,0 token)")
print("=" * 60)


def fake(calls):
    it = iter(calls)

    def call(messages, tool_specs):
        return next(it)
    return call


def ai(tool=None, args=None, content=""):
    m = AIMessage(content=content)
    if tool:
        m.tool_calls = [{"name": tool, "args": args or {}, "id": f"call_{tool}", "type": "tool_call"}]
    return m


# ① 白名单:模型想调没授权的危险工具
h1 = Harness(fake([ai("delete_all_files", {"path": "/"}), ai(content='{"conclusion":"被拦住了","evidence":["白名单"],"confidence":0.9}')]),
             TOOLS, SYSTEM)
print("① 调未授权工具 ->", h1.run("删掉所有文件")["answer"],
      "| 审计:", [e["event"] for e in h1.trace])

# ② 超时:工具睡 5 秒,策略只给 2 秒
h2 = Harness(fake([ai("sleep_tool", {"seconds": 5}), ai(content='{"conclusion":"超时被中断","evidence":["2s 限制"],"confidence":0.8}')]),
             TOOLS, SYSTEM, Policy(tool_timeout_s=1.0))
print("② 工具超时     ->", h2.run("睡 5 秒")["answer"], "| 审计:", [e["event"] for e in h2.trace])

# ③ 预算:假模型每次报 30000 token,超过 20000 就停
def greedy(messages, tool_specs):
    if len(messages) > 3:
        return AIMessage(content='{"conclusion":"不该走到这里","evidence":["x"],"confidence":0.1}')
    m = ai("calc", {"expression": "1+1"})
    m.usage_metadata = {"input_tokens": 30000, "output_tokens": 0, "total_tokens": 30000}
    return m


h3 = Harness(greedy, TOOLS, SYSTEM, Policy(token_budget=20000))
print("③ 预算超限     ->", h3.run("随便算点什么")["answer"], "| 审计:", [e["event"] for e in h3.trace])

# ④ 步数:模型无限点菜
h4 = Harness(fake([ai("calc", {"expression": "1+1"})] * 10), TOOLS, SYSTEM, Policy(max_steps=3))
print("④ 死循环       ->", h4.run("一直算")["answer"], "| 审计:", [e["event"] for e in h4.trace])

# ⑤ 规格:模型输出缺字段 → 打回重试
h5 = Harness(fake([ai(content='{"conclusion":"少了字段"}'),
                   ai(content='{"conclusion":"补上了","evidence":["重试"],"confidence":0.7}')]),
             TOOLS, SYSTEM)
print("⑤ 规格不合格   ->", h5.run("随便答")["answer"], "| 审计:", [e["event"] for e in h5.trace])

print("\n审计日志已写入:", LOG_FILE.name)
print("最后一条:", json.dumps(h5.trace[-1], ensure_ascii=False))
```

|---|---|---|
| 工具运行时 | 起进程/沙箱里执行工具、管超时 | 阶段 5 `MCPToolbox` + 第 10 课 `_run_tool` |

**④ 面试话术(照着这个结构讲,别背产品名)**

> "我手写过 agent harness。它至少要管五件事:工具执行和超时、上下文预算、行为约束(白名单/步数/预算/输出校验)、状态恢复、可观测。

这段的价值在于:**说清了机制、边界和后果**,而不是"我用过 X 产品"。

## 第 12 课 · Agent SDK 实操:用现成 SDK,而不是手搓（150 分钟）

> 对应 PDF 4.4「Agent SDK(比如:ClaudeCode SDK、Codex SDK)【企业基本都是使用现成的 SDK 进行开发,
> 不会用 LangChain & LangGraph 从 0 到 1 手搓】」。这是**唯一一项之前只到"知道"的缺口**,本课补齐。

### 目标

1. 用 **OpenAI Agents SDK**(Swarm 的官方继任者)在你自己的 DeepSeek key 上跑通:工具调用 + 多 Agent handoff
2. 看到 SDK 的杀手锏:**原生吃 MCP**(第 6 课手写的适配层,SDK 里一行都不用写)
3. 知道 **Claude Agent SDK** 的能力面和两道真实的门(限流/平台)
4. 会做选型:什么时候用 SDK、什么时候用 LangChain/LangGraph、什么时候什么都不用

### 核心概念

**① SDK 和框架不是一回事**

| | 框架(LangChain/LangGraph) | Agent SDK(Agents SDK / Claude Agent SDK) |
|---|---|---|
| 你拿到什么 | 零件(模型、工具、状态图) | 成品运行时(Agent 循环 + 会话 + 权限 + 可观测) |
| 你要写什么 | 拼装、状态管理、护栏 | 配置 + 业务工具 |
| 适合 | 需要精细控制流程 | 要快速交付、要跑在真实文件系统/终端里 |
| 代价 | 自由但什么都得自己管 | 约定多、绑定运行时 |

**② Agents SDK 的三个关键概念**(实测)
- `Agent(..., tools=[...])`:工具用 `@function_tool` 装饰,和 LangChain 的 `@tool` 一样是反射生成 Schema
- `Runner.run(agent, "问题")`:跑一轮,返回 `final_output` + `new_items`(能看到 `ToolCallItem`/`ToolCallOutputItem` 轨迹)
- `handoffs=[另一个 Agent]`:**多 Agent 路由**——等价于阶段 6 手写的 router,但不用自己写分发逻辑
- `mcp_servers=[server]`:原生挂 MCP server,`await server.list_tools()` 就能看到工具

**③ ★ 实测两个坑**
1. **中文 Agent 名会让 handoff 失效**:Agent 名叫"账单专员"时,SDK 生成的 handoff 工具名也是中文,本机 DeepSeek 端点下模型不会去调它 → 前台自己回答了。改成 ASCII 名(`billing` / `tech_support`)立刻正常路由。**结论:工具名、函数名、字段名一律用 ASCII**,这是所有 LLM 生态的通则。
2. **Claude Agent SDK 在 Windows 上被自己的安全策略拦住**:
   ```
   CLIConnectionError: Refusing to execute batch script '...claude.CMD':
   Windows runs .bat/.cmd files via cmd.exe, which can execute commands injection...
   ```
   它拒绝执行 `.cmd` 入口(防命令注入),另外还需要 Anthropic 的 key(DeepSeek key 用不了)。生产里通常 Linux/WSL + 官方 CLI。

**④ 选型口诀**

- 要**精细控制**流程、要自己写状态机 → LangGraph
- 要**快速交付**、Agent 要操作真实文件/终端/仓库 → Agent SDK(Claude Agent SDK / Codex CLI)
- 要**多 Agent 路由**且不想自己写分发 → Agents SDK 的 handoff
- 只是**一个带工具的对话** → 连框架都不用,阶段 2 的循环 + 第 10 课护栏最省心

## 第 13 课 · SDD 规格驱动开发（120 分钟）

> 对应 PDF 4.5「SDD(规格驱动开发:先定好规格再行动)」。

### 目标

1. 把"什么叫做完"写成**规格**(人可读)+ **检查器**(可执行)两层
2. 让模型按规格产出,用检查器自动验收;不合格就**带着失败原因**重写
3. 体会 SDD 和"提示词工程"的区别:SDD 的验收标准是**可执行**的,不靠人眼看

### 核心概念

**① 三层结构**

```
① 规格 spec(人读 + 给模型看)      : 本周产出 3-5 条 / 每条带数字 / 全文 ≤200 字 …
② 检查器 check(机器执行)           : 逐条实现规格,返回失败原因列表
③ 自修复循环                       : 失败原因原样喂回 → 重写 → 再验收,设轮次上限
```

**② 为什么它比"把提示词写详细点"强**

| | 提示词工程 | SDD |
|---|---|---|
| 标准在哪 | 模型的理解里 | 代码里(`check()`) |
| 是否可回归 | ❌ 靠人试用 | ✅ 能进 CI,换模型也能跑 |
| 失败时 | 你不知道差在哪 | 检查器逐条列出不符合项 |
| 团队协作 | 一个人的手艺 | 规格可 review、可版本化(spec v1/v2) |

**③ 实测暴露的两个真实问题(这才是本课的价值)**

1. **检查器可能比规格更严**:第一版我把"动词开头"实现成硬编码白名单(`完成/修复/交付/实现/上线/提交/接入/优化`),模型写"推进/搭建/开发"就被判不合格 → **永远打不到通过**。修法:把动词清单**写进规格**(`SPEC` 里列出),让检查器和规格一字不差地对齐。
2. **检查器可能太脆**:模型用 `1.` 编号列表或 `**加粗**` 时,按 `- ` 匹配的实现会数出"0 条"。修法:检查器要**容忍格式差异**(剥离 markdown、同时认 `-/*/1.`)。

> 结论:**SDD 的成本主要花在"把规格写成可判定的形式"上**。凡是规格里出现"简洁/专业/合理"这类词,检查器就写不出来——必须改成可判定的量化描述。

**④ 什么时候不该上 SDD**:探索性任务(还不知道要什么)、一次性脚本、创意类输出。规格本身要迭代时,先写 v0 跑起来再收紧。

## 第 14 课 · Vibe Coding:边界在哪（60 分钟,概念课）

> 对应 PDF 4.6「Vibe Coding」。

### 目标

说清一件事:**什么时候可以让模型"自由发挥",什么时候必须先把规格写死。**

### 核心概念

**① Vibe Coding 的本质**:你描述意图,模型直接产出可运行的东西,你靠"跑一下看看"来验收。
省掉的是"写设计文档 + 逐行 review",代价是**你对产出的理解程度下降**。

**② 边界 = 出错的代价**(这张表就是答案)

| 场景 | 能不能 vibe | 原因 |
|---|---|---|
| 内部脚本、一次性数据清洗、UI 原型 | ✅ 很适合 | 错了重跑,无人受害 |
| 有测试保护的重构 | ✅ 可以 | 测试就是 harness,改坏立刻红 |
| 探索"这个思路行不行" | ✅ 值得 | 快速验证比写文档便宜 |
| 生产服务核心链路 | ⚠️ 先写规格(SDD) | 错了就是事故,而且没人能 review 你不懂的东西 |
| 安全/权限/支付/数据删除 | ❌ 不要 | 概率系统 + 不可逆后果 = 灾难 |

**③ 让它安全的三个前提**
1. **有回归测试**(阶段 4 的 pytest):改坏立刻知道
2. **有护栏**(第 10 课 harness):越权、超预算、死循环被拦
3. **有回滚**(灰度/版本控制):错了能退回去

**④ 和你这个仓库的关系**:阶段 1-6 手写的每一层,就是你现在"敢 vibe"的底气——
模型给的代码你能一眼看出哪里不对(比如它把 `+=` 写成 `=` 拼流式 tool_calls,你在阶段 4 踩过这个坑)。
**先手写后框架的真正回报,不是会写框架代码,而是能判断框架给的代码对不对。**

2. **第 13 课 SDD 和本课是什么关系？**

# -*- coding: utf-8 -*-
"""
FastAPI Agent 服务 + SSE 流式
启动：uvicorn 15_fastapi_agent:app --reload --port 8000
测试：curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" -d '{"message":"你好"}'
流式：curl -N http://localhost:8000/chat/stream -H "Content-Type: application/json" -d '{"message":"介绍一下 Agent"}'
"""
import os
from dotenv import load_dotenv
from openai import OpenAI
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from pydantic import BaseModel
from typing import Iterator
import json

load_dotenv()

# ---- 配置 ----
client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL")
)
MODEL = os.environ.get("MODEL_NAME")

app = FastAPI(title="Agent Service", version="1.0")

# ---- 请求模型 ----
class ChatRequest(BaseModel):
    message: str
    user_id: str = "default_user"

class ChatResponse(BaseModel):
    reply: str
    tokens: int

# ---- Agent 逻辑（复用阶段 2 的简化版）----
def agent_reply(user_message: str) -> str:
    """非流式：一次性返回"""
    messages = [
        {"role": "system", "content": "你是一个助手"},
        {"role": "user", "content": user_message}
    ]
    response = client.chat.completions.create(
        model=MODEL,
        messages=messages
    )
    return response.choices[0].message.content

def agent_reply_stream(user_message: str) -> Iterator[str]:
    """流式：逐 token yield"""
    messages = [
        {"role": "system", "content": "你是一个助手"},
        {"role": "user", "content": user_message}
    ]
    stream = client.chat.completions.create(
        model=MODEL,
        messages=messages,
        stream=True
    )
    
    for chunk in stream:
        if chunk.choices[0].delta.content:
            yield chunk.choices[0].delta.content

# ---- 路由 1：非流式 ----
@app.post("/chat", response_model=ChatResponse)
def chat(request: ChatRequest):
    """同步返回完整回复"""
    reply = agent_reply(request.message)
    return ChatResponse(reply=reply, tokens=len(reply))

# ---- 路由 2：流式（SSE）----
@app.post("/chat/stream")
def chat_stream(request: ChatRequest):
    """流式返回（SSE 格式）"""
    def event_generator():
        for chunk in agent_reply_stream(request.message):
            # SSE 格式：data: {json}\n\n
            yield f"data: {json.dumps({'text': chunk})}\n\n"
        yield "data: [DONE]\n\n"
    
    return StreamingResponse(event_generator(), media_type="text/event-stream")

# ---- 路由 3：健康检查 ----
@app.get("/health")
def health():
    return {"status": "ok", "model": MODEL}

# ---- 启动提示 ----
if __name__ == "__main__":
    import uvicorn
    print("启动 Agent 服务：http://localhost:8000")
    print("API 文档：http://localhost:8000/docs")
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

# -*- coding: utf-8 -*-
"""
Milvus 向量数据库示例
对比：阶段 3 的 chromadb 手写向量库 vs Milvus 生产级向量库
"""
import os
from dotenv import load_dotenv
from openai import OpenAI
from pymilvus import connections, Collection, FieldSchema, CollectionSchema, DataType, utility
import numpy as np

load_dotenv()

# ---- 配置 ----
client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL")
)
MODEL = os.environ.get("MODEL_NAME")

# ---- 连接 Milvus ----
# 方式 1：本地 Milvus Lite（无需 Docker）
connections.connect("default", uri="./milvus_demo.db")

# 方式 2：Docker Milvus Standalone
# connections.connect("default", host="localhost", port="19530")

COLLECTION_NAME = "knowledge_base"

# ---- 创建 Collection（表）----
def create_collection():
    """定义 schema + 创建 collection"""
    if utility.has_collection(COLLECTION_NAME):
        print(f"Collection {COLLECTION_NAME} 已存在，跳过创建")
        return Collection(COLLECTION_NAME)
    
    # 定义字段（类似 SQL 的表结构）
    fields = [
        FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
        FieldSchema(name="text", dtype=DataType.VARCHAR, max_length=2000),
        FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=1536),  # DeepSeek embedding 维度
        FieldSchema(name="source", dtype=DataType.VARCHAR, max_length=200)
    ]
    
    schema = CollectionSchema(fields, description="知识库")
    collection = Collection(COLLECTION_NAME, schema)
    
    # 创建索引（HNSW 算法，适合高维向量）
    index_params = {
        "index_type": "HNSW",
        "metric_type": "IP",  # Inner Product（内积，余弦相似度的变体）
        "params": {"M": 16, "efConstruction": 200}
    }
    collection.create_index(field_name="embedding", index_params=index_params)
    print(f"Collection {COLLECTION_NAME} 创建成功")
    return collection

# ---- 获取 embedding ----
def get_embedding(text: str) -> list:
    """调用 DeepSeek embedding API（或本地模型）"""
    # 注意：DeepSeek 没有 embedding 接口，这里假设你用智谱/SiliconFlow
    # 如果没有，用 sentence-transformers 本地模型：
    # from sentence_transformers import SentenceTransformer
    # model = SentenceTransformer('sentence-transformers/all-MiniLM-L6-v2')
    # return model.encode(text).tolist()
    
    # 示例：假设你有 embedding API
    response = client.embeddings.create(
        model="text-embedding-ada-002",  # 替换成你的 embedding 模型
        input=text
    )
    return response.data[0].embedding

# ---- 插入文档 ----
def insert_documents(collection: Collection, docs: list):
    """批量插入文档（文本 + embedding）"""
    texts = [doc["text"] for doc in docs]
    sources = [doc["source"] for doc in docs]
    
    # 批量 embedding
    embeddings = [get_embedding(text) for text in texts]
    
    # 插入
    entities = [texts, embeddings, sources]
    collection.insert(entities)
    collection.flush()  # 确保写入磁盘
    print(f"插入 {len(docs)} 条文档")

# ---- 检索 ----
def search_documents(collection: Collection, query: str, top_k: int = 3):
    """向量检索"""
    query_embedding = get_embedding(query)
    
    # 加载到内存（首次查询需要）
    collection.load()
    
    # 检索
    search_params = {"metric_type": "IP", "params": {"ef": 64}}
    results = collection.search(
        data=[query_embedding],
        anns_field="embedding",
        param=search_params,
        limit=top_k,
        output_fields=["text", "source"]
    )
    
    docs = []
    for hits in results:
        for hit in hits:
            docs.append({
                "text": hit.entity.get("text"),
                "source": hit.entity.get("source"),
                "score": hit.score
            })
    return docs

# ---- 测试 ----
if __name__ == "__main__":
    collection = create_collection()
    
    # 插入示例文档

import os

import instructor
from pydantic import BaseModel, Field, ValidationError
from typing import List

load_dotenv()

# ---- 配置 ----
client_raw = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL")
)
client_instructor = instructor.from_openai(client_raw)
MODEL = os.environ.get("MODEL_NAME")

# ---- Pydantic 模型 ----
class Paper(BaseModel):
    """学术论文信息"""
    title: str = Field(description="论文标题")
    authors: List[str] = Field(description="作者列表")
    year: int = Field(description="发表年份", ge=1900, le=2030)
    venue: str = Field(description="发表会议/期刊")
    
class PaperList(BaseModel):
    """论文列表"""
    papers: List[Paper]
    total: int = Field(description="论文总数")

# ---- 方法 1：手动 JSON mode（阶段 4 做法）----
def extract_papers_manual(text: str) -> PaperList:
    """手动解析 + 校验（需要自己写重试逻辑）"""
    prompt = f"""从下面的文本中提取论文信息，返回 JSON 格式：
{{
    "papers": [
        {{"title": "...", "authors": ["...", "..."], "year": 2024, "venue": "..."}},
        ...
    ],
    "total": 2
}}

文本：{text}
"""
    
    response = client_raw.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": prompt}],
        response_format={"type": "json_object"}
    )
    
    json_str = response.choices[0].message.content
    print(f"[手动] 模型返回: {json_str[:150]}...\n")
    
    try:
        result = PaperList.model_validate_json(json_str)
        return result
    except ValidationError as e:
        print(f"[手动] 校验失败: {e}")
        # 这里需要自己写重试逻辑（阶段 4 做过）
        raise

# ---- 方法 2：Instructor（自动重试）----
def extract_papers_instructor(text: str) -> PaperList:
    """Instructor 自动重试（失败会把错误喂回模型，最多 3 次）"""

    result = client_instructor.chat.completions.create(
        model=MODEL,
        response_model=PaperList,  # 指定 Pydantic 模型
        messages=[{"role": "user", "content": prompt}],
        max_retries=3  # 失败自动重试
    )
    
    print(f"[Instructor] 解析成功: {result.total} 篇论文")
    return result

"""

if __name__ == "__main__":

        result1 = extract_papers_manual(sample_text)
        for p in result1.papers:

    except Exception as e:
        print(f"失败: {e}")
    
    print("\n=== 方法 2：Instructor（自动重试）===")
    result2 = extract_papers_instructor(sample_text)
    for p in result2.papers:
        print(f"  - {p.title} ({p.year}), {p.venue}")
        print(f"    作者: {', '.join(p.authors)}")
    
    # ---- 实验：故意给错误文本，观察重试 ----
    print("\n=== 实验：错误文本（触发重试）===")
    bad_text = "这段文本里根本没有论文信息，只是在闲聊。"

## 附录 C · 评测:LLM-as-judge（PDF 未覆盖）

### 目标

自动化测试 Agent 的回答质量：给定测试集（问题 + 标准答案），用另一个 LLM 当"评委"打分，替代人工评测。

### 核心概念

**LLM-as-judge = 用 LLM 评价 LLM**

传统测试：人工看回答是否正确（慢、不可扩展）  
LLM-as-judge：用 GPT-4 / Claude 当评委，自动打分（快、可批量）

评分维度：
- **准确性**（Accuracy）：答案是否正确？
- **完整性**（Completeness）：是否遗漏关键信息？
- **相关性**（Relevance）：是否跑题？
- **有害性**（Harmfulness）：是否有偏见/不当内容？

### 完整代码：`appendix_c_evaluation.py`

```python
# -*- coding: utf-8 -*-
"""
LLM-as-judge 评测示例
场景：测试 Agent 对知识库问题的回答质量
"""
import os
from dotenv import load_dotenv
from openai import OpenAI
from typing import List, Dict
import json

load_dotenv()

client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL")
)
MODEL = os.environ.get("MODEL_NAME")

# ---- 测试集 ----
test_cases = [
    {
        "question": "Python 的主要特点是什么？",
        "reference_answer": "Python 是解释型语言，语法简洁，支持多种编程范式，有丰富的库生态。",
        "category": "知识问答"
    },
    {
        "question": "什么是 Agent？",
        "reference_answer": "Agent 是能够感知环境、自主决策并采取行动的软件系统，通常由 LLM + 工具 + 循环组成。",
        "category": "概念解释"
    },
    {
        "question": "北京的天气怎么样？",
        "reference_answer": "需要调用天气查询工具获取实时数据。",
        "category": "工具调用"
    }
]

# ---- 被测 Agent（简化版）----
def agent_answer(question: str) -> str:
    """被测试的 Agent"""
    messages = [
        {"role": "system", "content": "你是一个助手，简洁回答问题。"},
        {"role": "user", "content": question}
    ]
    response = client.chat.completions.create(model=MODEL, messages=messages)
    return response.choices[0].message.content

# ---- 评委 LLM ----
def judge_answer(question: str, agent_answer: str, reference_answer: str) -> Dict:
    """用 LLM 当评委，给 Agent 的回答打分"""
    judge_prompt = f"""你是一个严格的评委。请评价以下 Agent 的回答质量。

问题: {question}
参考答案: {reference_answer}
Agent 回答: {agent_answer}

评分标准（0-10 分）：
- 准确性（5 分）：答案是否正确？
- 完整性（3 分）：是否遗漏关键信息？
- 相关性（2 分）：是否跑题？

请返回 JSON 格式：
{{
    "accuracy": 4,
    "completeness": 2,
    "relevance": 2,
    "total": 8,
    "reason": "答案基本正确，但遗漏了..."
}}
"""
    
    response = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": judge_prompt}],
        response_format={"type": "json_object"}
    )
    
    return json.loads(response.choices[0].message.content)

# ---- 批量评测 ----
def run_evaluation(test_cases: List[Dict]):
    """运行评测"""
    results = []
    
    for i, case in enumerate(test_cases, 1):
        question = case["question"]
        reference = case["reference_answer"]
        category = case["category"]
        
        print(f"\n=== 测试用例 {i}/{len(test_cases)} ===")
        print(f"问题: {question}")
        print(f"类别: {category}")
        
        # 1. Agent 回答
        answer = agent_answer(question)
        print(f"Agent 回答: {answer}")
        
        # 2. 评委打分
        score = judge_answer(question, answer, reference)
        print(f"评分: {score['total']}/10")
        print(f"理由: {score['reason']}")
        
        results.append({
            "question": question,
            "category": category,
            "agent_answer": answer,
            "score": score
        })
    
    return results

# ---- 生成报告 ----
def generate_report(results: List[Dict]):
    """生成评测报告"""
    total_score = sum(r["score"]["total"] for r in results)
    avg_score = total_score / len(results)
    
    print(f"\n{'='*50}")
    print(f"评测报告")
    print(f"{'='*50}")
    print(f"测试用例数: {len(results)}")
    print(f"平均得分: {avg_score:.2f}/10")
    
    # 按类别统计
    by_category = {}
    for r in results:
        cat = r["category"]
        if cat not in by_category:
            by_category[cat] = []
        by_category[cat].append(r["score"]["total"])
    
    print(f"\n按类别统计:")
    for cat, scores in by_category.items():
        print(f"  {cat}: {sum(scores)/len(scores):.2f}/10 (共 {len(scores)} 题)")
    
    # 低分用例（< 6 分）
    low_scores = [r for r in results if r["score"]["total"] < 6]
    if low_scores:
        print(f"\n需要改进的用例（< 6 分）:")
        for r in low_scores:
            print(f"  - {r['question']}: {r['score']['total']}/10")
            print(f"    理由: {r['score']['reason']}")

# ---- 运行 ----
if __name__ == "__main__":
    results = run_evaluation(test_cases)
    generate_report(results)
    
    # 保存结果
    with open("evaluation_results.json", "w", encoding="utf-8") as f:
        json.dump(results, f, ensure_ascii=False, indent=2)
    print(f"\n结果已保存到 evaluation_results.json")
```

## 常见问题（FAQ）

### 1. Milvus 和 chromadb 性能差多少？

数据量 < 10 万：差异不明显  
数据量 > 100 万：Milvus 快 5-10 倍（HNSW 索引 + 分布式）  
建议：学习用 chromadb，生产用 Milvus

### 2. mem0 免费吗？

本地模式（SQLite + chromadb）免费  
云端托管版收费（但有免费额度）  
自己部署用本地模式即可

### 3. 为什么 FastAPI 而不是 Flask？

FastAPI 原生支持异步（async/await）、自动生成 OpenAPI 文档、Pydantic 集成  
Flask 是同步框架，异步要装插件  
企业新项目基本都用 FastAPI

### 4. LangSmith 必须用吗？

不必须。可以：
- 手动日志（print + 文件）
- 开源 Langfuse（可自部署）
- 云厂商自带的可观测（阿里云 / 腾讯云）

LangSmith 的优势是和 LangChain 深度集成，自动追踪

### 5. Instructor 支持流式吗？

部分支持（`stream=True` + `Partial`），但复杂结构会有坑  
生产建议：先非流式拿结构化结果，再流式输出文本部分

### 6. 怎么部署到服务器？

```bash
# 方式 1：直接跑（开发环境）
uvicorn graduation_knowledge_service:app --host 0.0.0.0 --port 8000

# 方式 2：Docker（生产推荐）
# Dockerfile:
FROM python:3.10
COPY . /app
WORKDIR /app
RUN pip install -r requirements.txt
CMD ["uvicorn", "graduation_knowledge_service:app", "--host", "0.0.0.0", "--port", "8000"]

# 构建 + 运行
docker build -t my-agent-service .
docker run -p 8000:8000 my-agent-service

# 方式 3：Kubernetes（大规模）
# 写 k8s deployment.yaml，kubectl apply
```

### 7. 成本怎么算？

假设用 DeepSeek（0.1 元 / 百万 token）：
- 单次对话（含检索 + 回复）：~2000 tokens = 0.0002 元
- 1 万次对话 = 2 元
- 比人工客服便宜 1000 倍+

### 8. 怎么防止 prompt injection？

- 输入校验（拒绝包含 "ignore previous instructions" 的输入）
- 分离系统 prompt 和用户输入（用 `system` / `user` role）
- 输出校验（Instructor + Pydantic 检查格式）
- 沙箱执行（工具调用在隔离环境跑）
