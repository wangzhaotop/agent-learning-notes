## 第 0 课 · 概念 + 阅读(先读后敲,这课没有代码)

**核心认知(背下来)**:

- 模型**从不执行任何东西**。它只会"点菜":输出一段结构化 JSON,说"我想调用 get_current_time,参数是 {}"——这就是 function calling 协议
- 真正动手的是**你的 Python 代码**:执行函数、拿到结果
- 结果以 `role=tool` 的消息喂回给模型,它基于结果继续说话或继续点菜
- **Agent = LLM + 工具 + while 循环**。把"点菜→做菜→喂回去→再点菜"套进循环,循环结束于模型给出最终回答——这就是所有 Agent 框架替你做的全部事情

**先读这三份(合计约 1 小时)**:

1. [DeepSeek 官方 API 文档](https://api-docs.deepseek.com)的「**Function Calling**」指南(https://api-docs.deepseek.com/guides/function_calling)——请求/响应字段 + 示例
2. [OpenAI Function Calling 指南](https://platform.openai.com/docs/guides/function-calling)——英文权威,重点看请求/响应里 `tools`、`tool_calls`、`role=tool` 三块
3. Anthropic《[Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents)》——通读,重点体会"能用简单工作流解决的就别上复杂 Agent"

## 第 1 课 · 00_first_tool_call.py — 手动走一遍完整回合

**目标**:不加循环、不加封装,用最笨的方式把"点菜→做菜→喂回去→最终回答"走一遍。这一课的每个步骤,就是所有 Agent 框架的黑盒内部。

**新概念**:
- `tools` 参数:用 JSON Schema 向模型"介绍"你的函数——模型看不见你的 Python 代码,只看得见说明书
- 返回的 `message.tool_calls`:模型的点菜单
- ★ 大坑:`tool_call.function.arguments` 是 **JSON 字符串**,不是字典,必须 `json.loads`

```python
import json
import os
from datetime import datetime

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL"),
)
MODEL = os.environ.get("MODEL_NAME")

# ---- 第 1 步:定义一个真正的工具函数(模型之后"点"的就是它) ----
def get_current_time():
    """获取当前的日期和时间"""
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S %A")

# ---- 第 2 步:用 JSON Schema 向模型"介绍"这个工具 ----
# description 写得越清楚,模型越知道什么时候该用它
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_current_time",
            "description": "获取当前的日期和时间",
            "parameters": {
                "type": "object",
                "properties": {},     # 这个工具不需要参数
                "required": [],
            },
        },
    }
]

# ---- 第 3 步:发消息,带上工具说明书 ----
messages = [{"role": "user", "content": "现在几点了?"}]
response = client.chat.completions.create(
    model=MODEL,
    messages=messages,
    tools=tools,
)
msg = response.choices[0].message

# ---- 第 4 步:亲眼看看模型的"点菜单" ----
if not msg.tool_calls:
    # 模型有权不调用工具直接回答——什么时候调、什么时候不调,是它自己判断的
    print("模型没有调用工具,直接回答了:", msg.content)
    raise SystemExit

print("=== 模型想调用的工具 ===")
print(msg.tool_calls)      # 此时 msg.content 往往是 None,回复藏在 tool_calls 里

tool_call = msg.tool_calls[0]
print(f"工具名:{tool_call.function.name}")

# ★ 大坑:arguments 不是字典,是【JSON 字符串】!
print(f"原始参数:{tool_call.function.arguments}(类型:{type(tool_call.function.arguments)})")
args = json.loads(tool_call.function.arguments)
print(f"解析后的参数:{args}")

# ---- 第 5 步:你的代码执行工具(模型做不到这件事) ----
result = get_current_time(**args)    # **args:把字典展开成关键字参数
print(f"执行结果:{result}")

# ---- 第 6 步:把"点菜记录"和"菜"都写进历史,再问模型一次 ----
# model_dump() 把 SDK 对象转成普通字典:既能放进 messages 发回去,以后也能存 JSON
# dict 里会带着 reasoning_content(思考型模型的"草稿纸"),先照原样回传,第 3 课后再想瘦身
messages.append(msg.model_dump(exclude_none=True))
messages.append({
    "role": "tool",                  # 工具结果固定用 role=tool
    "tool_call_id": tool_call.id,    # 和这次点菜一一对应
    "content": result,               # 必须是字符串
})

final = client.chat.completions.create(model=MODEL, messages=messages)
print(f"模型最终回答:{final.choices[0].message.content}")
```

**自测/实验**:
1. 把问题换成"1 加 1 等于几?"再跑——模型不点菜直接回答了。体会:**用不用工具是模型自己决定的**,你的代码只是备好了菜单。
2. `print(response)` 看完整返回结构,找到 `finish_reason`——点菜时它是什么值?
3. 如果模型传了说明书里没有的参数,`get_current_time(**args)` 会抛 `TypeError`。先跑几次看看有没有发生,想想后面怎么兜底(第 2 课解决)。
4. 加一行 `print(msg.reasoning_content)` 看模型的"草稿纸"——它调工具前在想什么;再看 `response.usage` 里的 `reasoning_tokens`,思考也是按 token 计费的。

## 第 2 课 · 01_tool_dispatch.py — 写一个"工具调度器"

**目标**:把第 1 课的手动步骤封装成 `run_tool_calls()`,配一张"名字 → 函数"映射表,再让一个问题能连续多轮点菜。

**新概念**:
- 映射表:`TOOL_IMPLS = {"名字": 函数}`,Java 视角就是 `Map<String, Function>`
- 兜底:工具不存在、参数解析失败、执行报错,都不能让程序崩——把错误信息**作为结果**喂回模型,它自己会想办法
- `for...else`:Python 特有,循环**没被 break 正常走完**才执行 else(Java 没有这语法)

```python
import json
import os
from datetime import datetime

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL"),
)
MODEL = os.environ.get("MODEL_NAME")

# ---- 三个真实工具 ----
def get_current_time():
    """获取当前的日期和时间"""
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S %A")

def write_file(path, content):
    """把文本内容写入指定文件(覆盖原内容)"""
    with open(path, "w", encoding="utf-8") as f:
        f.write(content)
    return f"已写入 {path},共 {len(content)} 个字符"

def read_file(path):
    """读取指定文件的全部文本内容"""
    with open(path, "r", encoding="utf-8") as f:
        return f.read()

# ---- 向模型介绍这三个工具 ----
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_current_time",
            "description": "获取当前的日期和时间",
            "parameters": {"type": "object", "properties": {}, "required": []},
        },
    },
    {
        "type": "function",
        "function": {
            "name": "write_file",
            "description": "把文本内容写入指定文件,覆盖原内容",
            "parameters": {
                "type": "object",
                "properties": {
                    "path": {"type": "string", "description": "文件路径"},
                    "content": {"type": "string", "description": "要写入的文本内容"},
                },
                "required": ["path", "content"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "read_file",
            "description": "读取指定文件的全部文本内容",
            "parameters": {
                "type": "object",
                "properties": {
                    "path": {"type": "string", "description": "文件路径"},
                },
                "required": ["path"],
            },
        },
    },
]

# ---- 名字 → 函数 映射表:调度器的核心 ----
TOOL_IMPLS = {
    "get_current_time": get_current_time,
    "write_file": write_file,
    "read_file": read_file,
}

def run_tool_calls(assistant_msg, history):
    """执行模型点 的所有工具,每个结果作为 role=tool 消息追加进历史"""
    for tool_call in assistant_msg.tool_calls:
        name = tool_call.function.name

        # 兜底 1:参数解析失败就当空参数
        try:
            args = json.loads(tool_call.function.arguments)
        except json.JSONDecodeError:
            args = {}

        func = TOOL_IMPLS.get(name)
        if func is None:
            # 兜底 2:模型点了一道菜单上没有的菜
            result = f"错误:不存在名为 {name} 的工具"
        else:
            try:
                result = func(**args)
            except Exception as e:
                # 兜底 3:执行出错不崩程序,把错误告诉模型,它会自己调整
                result = f"工具执行出错:{e}"

        print(f"[工具] {name}({args}) -> {result}")
        history.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": str(result),     # 结果必须是字符串
        })

# ---- 一个可能连续点菜的问题:先写文件,再读回来确认 ----
messages = [{"role": "user", "content": "帮我在 todo.txt 里记一条:明天上午十点开会。记完后读一下这个文件,向我确认内容。"}]

for round_i in range(5):
    response = client.chat.completions.create(
        model=MODEL, messages=messages, tools=tools,
    )
    msg = response.choices[0].message
    messages.append(msg.model_dump(exclude_none=True))

    if not msg.tool_calls:              # 没有点菜 = 给出最终回答了
        print(f"最终回答:{msg.content}")
        break

    print(f"--- 第 {round_i + 1} 轮工具调用 ---")
    run_tool_calls(msg, messages)
else:
    # 5 轮全在点菜、没 break 出来,强制停止(防失控)
    print("连续 5 轮都在调工具,强制停止")
```

**自测/实验**:
1. 运行后数一数:这次任务模型点了几轮菜?每轮点了什么?对照 `[工具]` 日志。
2. 故意把 `TOOL_IMPLS` 里的 `"read_file"` 键名改错再跑——看"兜底 2"怎么工作,以及模型拿到错误信息后的表现。
3. 把问题简化成"现在几点",确认它一轮就结束。

## 第 3 课 · 02_mini_agent.py — Agent 诞生

**目标**:加上 `input()` 对话循环和跨轮记忆。**Agent = LLM + 工具 + while 循环**,写完这个,你就拥有一个完整的、不依赖任何框架的 Agent。

**新概念**:
- `agent_reply()`:一个把"循环点菜"包起来的函数——这是你以后所有 Agent 的骨架
- `MAX_STEPS`:给循环上保险,模型停不下来时强制刹车

```python
import json
import os
from datetime import datetime

from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

client = OpenAI(
    api_key=os.environ.get("OPENAI_API_KEY"),
    base_url=os.environ.get("OPENAI_BASE_URL"),
)
MODEL = os.environ.get("MODEL_NAME")

# ===== 工具部分:和第 2 课相同,照着敲一遍加深肌肉记忆 =====
def get_current_time():
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S %A")

def write_file(path, content):
    with open(path, "w", encoding="utf-8") as f:
        f.write(content)
    return f"已写入 {path},共 {len(content)} 个字符"

def read_file(path):
    with open(path, "r", encoding="utf-8") as f:
        return f.read()

# (三个工具的 tools 说明书和第 2 课完全一样,自己补全)

TOOL_IMPLS = {
    "get_current_time": get_current_time,
    "write_file": write_file,
    "read_file": read_file,
}

def run_tool_calls(assistant_msg, history):
    """同第 2 课,原样搬过来"""
    for tool_call in assistant_msg.tool_calls:
        name = tool_call.function.name
        try:
            args = json.loads(tool_call.function.arguments)
        except json.JSONDecodeError:
            args = {}
        func = TOOL_IMPLS.get(name)
        if func is None:
            result = f"错误:不存在名为 {name} 的工具"
        else:
            try:
                result = func(**args)
            except Exception as e:
                result = f"工具执行出错:{e}"
        print(f"[工具] {name}({args}) -> {result}")
        history.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": str(result),
        })

# ===== Agent 部分 =====
SYSTEM_PROMPT = "你是一个能使用工具的助手。需要查时间、读写文件时调用相应工具;回答保持简洁。"
MAX_STEPS = 10    # 单次提问最多允许的"点菜"轮数

messages = [{"role": "system", "content": SYSTEM_PROMPT}]

def agent_reply(user_input):
    """处理一句话:循环"点菜→执行",直到模型给出最终回答。
    这个函数就是 Agent 的心脏,毕业考你要闭卷重写它。"""
    messages.append({"role": "user", "content": user_input})
    for _ in range(MAX_STEPS):
        response = client.chat.completions.create(
            model=MODEL, messages=messages, tools=tools,
        )
        msg = response.choices[0].message
        messages.append(msg.model_dump(exclude_none=True))

        if not msg.tool_calls:
            return msg.content            # 最终回答,循环结束
        run_tool_calls(msg, messages)     # 否则执行工具,结果入历史,继续下一轮
    return "(达到最大步数,强制停止)"

print(f"Agent 已启动,模型:{MODEL}(exit 退出)")
while True:
    try:
        user_input = input("\n你: ").strip()
    except (KeyboardInterrupt, EOFError):
        print("\n再见!")
        break
    if user_input.lower() == "exit":
        break
    if not user_input:
        continue
    reply = agent_reply(user_input)
    print(f"AI: {reply}")
```

**必做实验(按顺序玩)**:
1. "现在几点了?" → 看 `[工具]` 日志
2. "帮我在 todo.txt 里记一条:明天买牛奶" → 打开 `todo.txt` 验证真的写进去了——**是模型指挥你的代码写的**
3. 接着问"我刚才让你记了什么?" → 它可能直接凭记忆回答,也可能重新调 `read_file`,两种都对,想明白为什么
4. "把 notes.txt 写入'Python 阶段 2 完成',然后读出来告诉我内容" → 连续多工具链

**自测**:
1. 把 `MAX_STEPS` 改成 1,问一个需要写文件的问题,会发生什么?
2. 为什么带 `tool_calls` 的 assistant 消息必须**先** append,tool 结果**紧跟其后**?手动调换顺序跑一次,把报错记下来。
3. `tools` 和 `TOOL_IMPLS` 分别是给谁看的?
4. 把 `read_file` 的 description 改成"查询天气",再问"我的 todo.txt 里有什么"——观察模型行为,体会 description 就是工具的"灵魂"。

## 阶段 2 常见报错速查

| 报错/现象 | 原因 | 解决 |
|---|---|---|
| `tool_calls` 为 None,模型直接回答 | 模型判断不需要工具 | 正常行为;检查 description 是否写得清楚 |
| `TypeError: ... got an unexpected keyword argument` | 模型传了说明书里没有的参数 | `run_tool_calls` 的兜底 3 已捕获;完善 parameters 定义 |
| `json.JSONDecodeError` | arguments 字符串不是合法 JSON | 打印原文看看;兜底 1 已捕获 |
| `An assistant message with 'tool_calls' must be followed by tool messages...` | 消息顺序错了 | assistant(tool_calls) 必须紧挨着它的 role=tool 结果 |
| `Invalid value for 'tool_call_id'` | role=tool 消息没带对 id | content 用的 `tool_call.id` 必须和点菜那条一一对应 |
| `Object of type ChatCompletionMessage is not JSON serializable` | 想直接 json.dump SDK 对象 | 先 `model_dump()` 转字典 |
| 模型反复调同一个工具停不下来 | 描述不清或任务无解 | 检查 description;确认 `MAX_STEPS` 生效 |
| `Model Not Exist` / 模型不存在 | MODEL_NAME 拼错 | 你账号可用:`deepseek-flash`、`deepseek-v4-pro`;用 `GET https://api.deepseek.com/models` 核实 |
| 对话越长单次请求越贵 | 思考型模型的 reasoning_content 草稿纸也堆在 messages 里 | 进阶:`model_dump` 后 `msg_dict.pop("reasoning_content", None)` 瘦身(实测不瘦身也能正常跑) |

**卡住的标准动作不变**:读报错最后一行 → 搜索 → 超 30 分钟,把代码 + 完整报错 + 你跑的原话一起贴给 ZCode。
