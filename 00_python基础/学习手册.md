## 第 5 课 · 05_面向对象.py — OOP:封装、继承、多态

**目标**:一个 `BaseTool` 抽象基类 + 两个子类 + 一个 `dataclass`,把封装/继承/多态一次走完——这正好就是阶段 4 手册里工具注册器的骨架。

**新概念**(只列和 Java 的差异点,相同的部分不啰嗦):

- `self` 就是 Java 的 `this`,区别是**必须显式写在方法参数第一位**;`__init__` 是初始化方法(真正的构造器是 `__new__`,一般不碰)
- 访问控制没有关键字:`_x` 单下划线是"受保护"的**君子协定**;`__x` 双下划线触发**名称改写**(实际存成 `_类名__x`),外部真摸不到;`__x__` 双侧下划线是魔术方法,自己别造
- 继承写法 `class Sub(Base)`,但**父类 `__init__` 不会自动执行**,要手动 `super().__init__()`(Java 会自动调)——新手第一大坑
- 多继承合法(Java 是单继承 + 接口),菱形冲突靠 **MRO**(方法解析顺序)裁决,`类名.__mro__` 能亲眼看顺序
- 多态不靠 interface:**鸭子类型**——不看血统,只要"有那个方法"就能一起用;想强制约束就用 `abc.ABC` + `@abstractmethod`,这是 Python 里最像 Java 抽象类/interface 的东西
- `@property` = getter,`@classmethod` = 静态工厂方法,`@dataclass` 一行顶 Java 的 `record` / Lombok `@Data`(自动生成 `__repr__`/`__eq__`)——后面阶段 4 的 Pydantic `BaseModel` 就是"带运行时校验的 dataclass"

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass


# ========== 1. 类与封装:__init__ / self / 访问控制 ==========
class BaseTool(ABC):
    """所有工具的父类——阶段 4 手册里的工具注册器就是这套套路"""

    description = "我是工具基类"          # 类属性:所有实例共享,= Java 的 static 字段

    def __init__(self):
        self._calls = 0                  # _单下划线 = "受保护",纯约定(Java 有 private,Python 靠自觉)

    @property
    def calls(self):                     # @property = Java 的 getter;调用写 t.calls,不是 t.calls()
        return self._calls

    @abstractmethod
    def run(self, args: str) -> str:
        """抽象方法:子类不实现,实例化直接报错——Python 版的 abstract / interface"""

    def invoke(self, args: str) -> str:
        """模板方法:计数、日志等公共逻辑封在父类,子类只管 run——这就是封装"""
        self._calls += 1
        print(f"[{self.__class__.__name__}] 第 {self._calls} 次被调用")
        return self.run(args)


class EchoTool(BaseTool):
    def run(self, args: str) -> str:
        return f"echo: {args}"


class UpperTool(BaseTool):
    def run(self, args: str) -> str:
        return args.upper()


class ReadFileTool(BaseTool):
    def __init__(self, encoding: str = "utf-8"):
        super().__init__()               # 不写这行,父类 __init__ 不会自动执行,_calls 就没初始化
        self.__encoding = encoding       # __双下划线:被改写成 _ReadFileTool__encoding,外部摸不到

    def run(self, args: str) -> str:
        with open(args, encoding=self.__encoding) as f:   # open 的细节第 9 课讲
            return f.read()


# ========== 2. 多态:鸭子类型 ==========
# Java:先定 interface Tool,各实现类 implements;
# Python:不看血统看行为——只要"有 run 方法",就能塞进同一个列表循环调用
tools = [EchoTool(), UpperTool()]        # ReadFileTool 要读真文件,第 9 课学完再回头调它
for t in tools:
    print(t.invoke("hello"))             # 同一句 invoke,各自落到自己的 run(动态绑定)

print(tools[0].calls, tools[1].calls)    # 通过 @property 读:1 1

# BaseTool()                            # 打开试试:TypeError,抽象类不能实例化
# print(tools[0]._calls)                # 技术上能访问,但别——_ 是君子协定


# ========== 3. dataclass:一行顶 Java 的 record / Lombok @Data ==========
@dataclass
class AgentConfig:
    model: str
    max_steps: int = 5                   # 字段默认值 = 构造器重载
    temperature: float = 0.7

    @classmethod
    def cheap(cls):                      # @classmethod = Java 的静态工厂方法,cls 就是本类
        return cls(model="glm-4-flash", temperature=0.2)


cfg = AgentConfig(model="glm-4")
print(cfg)                               # 自动生成 __repr__,不用手写 toString
print(cfg == AgentConfig(model="glm-4")) # 自动生成 __eq__,按字段比——True
print(AgentConfig.cheap())
```

## 第 6 课 · 06_闭包与装饰器.py — 高阶函数:闭包、装饰器

**目标**:理解"函数是值" → 看懂闭包 → 手写带参数的装饰器 `@retry`。装饰器是阶段 4 `@tool` 注册器的核心语法,这课必须吃透。

**新概念**:

- **高阶函数**:函数能当参数、当返回值。Java 8 的 `Function<T,R>` / `Comparator` 你已经会,Python 更彻底:函数和 int 一个地位,能存变量、能进列表、能被返回
- **闭包**:内层函数"记住"外层函数的变量,外层函数返回后变量依然活着。Java 匿名内部类只能捕获 effectively final 的变量;Python 默认同样只读,但给了 `nonlocal` 这个"允许写"的开关
- **装饰器** = 接收函数、返回新函数的高阶函数 + `@` 语法糖。`@timed` 等价于 `f = timed(f)`
- **和 Java 注解的本质区别**:`@Tool` 注解只是贴标签,要等反射扫描器来读;Python 装饰器**当场就执行**,包装立即生效——这是两种语言哲学差异的绝佳例子
- `functools.wraps`:把原函数的 `__name__/__doc__` 抄回 wrapper——不加,被装饰的函数就"改名换姓"了(你原文件里已经验证过)
- **带参数的装饰器 = 三层套娃**:第 1 层收参数、第 2 层收函数、第 3 层干活

```python
import functools
import random
import time


# ========== 1. 高阶函数:函数和 int、str 一样,是个可以传来传去的值 ==========
def apply(func, x):                      # 函数当参数——Java 8 的 Function<T, R>
    return func(x)


print(apply(str.upper, "abc"))           # ABC
print(apply(lambda s: s * 2, "ab"))      # lambda = 箭头函数,只能写一个表达式

words = ["banana", "Fig", "apple"]
print(sorted(words))                     # ['Fig', 'apple', 'banana'] —— 大写按 ASCII 排在前面
print(sorted(words, key=str.lower))      # ['apple', 'banana', 'Fig'] —— key 指定按"小写形态"比
print(sorted(words, key=len))            # key 接一个函数 = Comparator.comparing(String::length)
# sorted/map/filter 都返回新对象、不动原列表——和 Java Stream 一个脾气


# ========== 2. 闭包:内层函数"记住"外层函数的变量 ==========
def make_counter():
    count = 0                            # 被内层函数捕获;外层函数返回后它依然活着

    def inc(step: int = 1) -> int:
        nonlocal count                   # 想改外层变量必须声明(只读则不用)
        count += step
        return count

    return inc                           # 返回函数本身,不是 inc()


counter = make_counter()
print(counter(), counter(), counter(10)) # 1 2 12——count 活在闭包里,不在全局
print(counter.__closure__)               # 捕获的变量就存在这些 cell 里


# ========== 3. 装饰器 = 接收函数、返回新函数的高阶函数 + @ 语法糖 ==========
def timed(func):
    @functools.wraps(func)               # 把原函数的 __name__/__doc__ 抄到 wrapper 上
    def wrapper(*args, **kwargs):        # 不管原函数什么签名都接得住
        t0 = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时 {time.perf_counter() - t0:.4f}s")
        return result
    return wrapper


@timed                                   # 等价于:slow_sum = timed(slow_sum)
def slow_sum(n: int) -> int:
    """求 0..n-1 的和"""
    return sum(range(n))


print(slow_sum(10_000_000))
print(slow_sum.__name__)                 # slow_sum,不是 wrapper——wraps 的功劳


# ========== 4. 带参数的装饰器:再包一层,一共三层 ==========
def retry(times: int):                   # 第 1 层:先收装饰器自己的参数
    def decorator(func):                 # 第 2 层:收函数(普通装饰器的本体)
        @functools.wraps(func)
        def wrapper(*args, **kwargs):    # 第 3 层:真正干活
            last_err = None
            for i in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:   # 异常语法第 7 课细讲,这里先抄用
                    last_err = e
                    print(f"  第 {i}/{times} 次失败:{e}")
            raise RuntimeError(f"重试 {times} 次仍失败") from last_err
        return wrapper
    return decorator


@retry(times=3)
def flaky_api() -> str:
    """模拟一个成功率约 30% 的接口"""
    if random.random() < 0.7:
        raise ConnectionError("网络抖动")
    return "调用成功"


try:
    print(flaky_api())
except RuntimeError as e:
    print(f"最终失败:{e}")

# ========== 5. 和你已写/将写的代码连线 ==========
# @retry          —— 06_my_chat.py 里 JSON 解析失败就可以靠它自动重试
# @tool(阶段 4)   —— 注册器装饰器:收函数 + 读 docstring 生成 Schema + 登记进字典
# Java 对比:@Tool 注解只是贴标签,等反射扫描器来读;Python 装饰器"当场就执行"
```

**自测**:

## 第 7 课 · 07_错误和异常.py — 错误和异常

**目标**:`try/except/else/finally` 全家桶 + 自定义异常 + 异常链。你在阶段 1 的 JSON 解析里已经"抄"过 try/except,这课补全原理。

**新概念**:

- 异常也是一棵继承树,和 Java 的 `Throwable` 家族同构:`except` 写父类能接住所有子类——所以**先子类后父类**,和 Java 的 catch 顺序规则一样
- 四个块:`try / except / else / finally`;`else` 是 Java 没有的——"没抛异常才走",把成功路径从 try 里搬出来,可读性更好
- `raise` = `throw`;自定义异常 = `class ToolError(Exception)` = `extends Exception`
- **异常链** `raise X from e` = Java 的 `new X(cause)`:包装重抛时保留因果链,`e.__cause__` 能看到根因
- **EAFP 风格**:Python 惯例是"先干,错了再接"(Easier to Ask Forgiveness than Permission);Java 常写的"先检查再取"叫 LBYL。但最常用的是 `dict.get(key, 默认值)` 这种自带兜底的 API
- **Agent 铁律**:工具炸了程序不能崩——在工具边界 catch 一切,把错误文本作为 tool result 喂回模型,模型看到报错会自己调整下一步(阶段 2 的 MAX_STEPS 循环就是靠这个活的)

```python
import json


# ========== 0. 异常是一棵继承树(和 Java 的 Throwable 家族同构) ==========
# BaseException
#  ├─ KeyboardInterrupt          ← Ctrl+C 就是它,别去接
#  └─ Exception                  ← 你该接住的都是它的子孙
#      ├─ ValueError             ← 值不合法:int("abc")
#      ├─ TypeError              ← 类型不匹配:"a" + 1
#      ├─ KeyError / IndexError  ← 字典没这键 / 列表越界
#      ├─ FileNotFoundError      ← open 一个不存在的文件
#      └─ RuntimeError           ← 运行期错误的兜底父类;自定义异常一般直接继承 Exception


# ========== 1. try / except / else / finally ==========
def safe_div(a, b):
    try:
        result = a / b
    except ZeroDivisionError:                # except = Java 的 catch
        print(f"  捕获除零:{a}/{b}")
        return None
    except TypeError as e:                   # as e = catch (ArithmeticException e)
        print(f"  捕获类型错误:{e}")
        return None
    else:                                    # Java 没有:try 没抛异常才走,成功路径单独放
        print(f"  成功:{a}/{b} = {result}")
        return result
    finally:                                 # 与 Java 相同:无论如何都执行
        print("  --- 本次计算结束 ---")


safe_div(6, 3)
safe_div(1, 0)
safe_div("a", 2)

# except 要先子类后父类:先写 except Exception 会"截胡"所有异常,
# 后面的具体 except 永远轮不到——和 Java 的 catch 顺序规则一样


# ========== 2. raise = throw;自定义异常 = extends Exception ==========
class ToolError(Exception):
    """工具执行失败——Agent 项目里最常自定义的异常"""


TOOL_IMPLS = {"echo": lambda s: s, "upper": str.upper}


def run_tool(name: str, args: str) -> str:
    if name not in TOOL_IMPLS:
        raise ToolError(f"未知工具:{name}")
    return TOOL_IMPLS[name](args)


try:
    print(" ", run_tool("echo", "hi"))
    print(" ", run_tool("fly", "to the moon"))
except ToolError as e:
    # Agent 铁律:工具炸了程序不能崩——把错误文本作为 tool result 喂回模型,
    # 模型看到报错会自己调整
    print(f"  捕获:{e} → 把这句话作为 tool result 喂回模型")


# ========== 3. 异常链:raise ... from e = Java 的 new X(cause) ==========
def parse_model_output(raw: str) -> dict:
    try:
        return json.loads(raw)
    except json.JSONDecodeError as e:
        raise RuntimeError(f"模型没按 JSON 返回:{raw!r}") from e   # 保留完整因果链


try:
    parse_model_output("我说的是人话,不是 JSON")
except RuntimeError as e:
    print(f"  捕获:{e}")
    print(f"  根因:{e.__cause__!r}")


# ========== 4. EAFP:Python 的行事风格 ==========
user = {"name": "WangZZZ"}

# LBYL(Java 常写):先检查再取 —— Look Before You Leap
if "mood" in user:
    print(user["mood"])
else:
    print("  LBYL:没有 mood 字段")

# EAFP(Python 常写):先推门,门锁了再配钥匙
try:
    print(user["mood"])
except KeyError:
    print("  EAFP:没有 mood 字段")

# 但最常用的其实是自带默认值的 API:
print(user.get("mood", "neutral"))
```

## 第 8 课 · 08_迭代器和生成器.py — 迭代器和生成器【面试重点】

**目标**:讲清 for 循环的本质;分清可迭代 vs 迭代器;熟练写生成器和生成器表达式。这一课按面试标准学——下面的自测题和速答表,每一条都可能原样出现在面试里。

**新概念**:

- **for 的本质只有三步**:`iter(可迭代)` 拿迭代器 → 循环 `next(it)` 取值 → 抛 `StopIteration` 就停。for 只是这三步的语法糖
- **Iterable vs Iterator(面试第一高频)**:可迭代只实现 `__iter__`(list/str/dict/file/range 都是);迭代器要 `__iter__` + `__next__`。关系:`iter(可迭代) → 迭代器`;迭代器一定是可迭代的,反之不成立
- **迭代器是一次性的**:取完就空,再遍历得到空——list 能反复 for,是因为每次 for 都 `iter()` 造一只"新手"
- **生成器**:带 `yield` 的函数,调用它**不执行函数体**,每次 `next()` 才走到下一个 yield 并暂停——惰性求值、省内存、还能表达无限序列
- **生成器表达式 `(x*x for x in ...)` vs 列表推导 `[...]`**:一个存公式、一个存结果,内存差一万倍
- **`yield from`**:把另一个可迭代对象的元素整个"接进来"
- **连回你已经写过的代码**:阶段 1 `02_stream.py` 里 `for chunk in response` ——SDK 返回的就是一个迭代器/生成器,一个 token 一个 token 吐,所以才有打字机效果;阶段 3 遍历文档切块也是它。学完这课,那段代码你就彻底看懂了

```python
import sys


# ========== 1. for 循环的本质:iter() + next() + StopIteration ==========
nums = [10, 20, 30]

it = iter(nums)                  # 1) for 先向列表要一个迭代器:nums.__iter__()
while True:
    try:
        n = next(it)             # 2) 每轮调 next(it) 拿下一个:it.__next__()
        print(n)
    except StopIteration:        # 3) 拿完了,迭代器抛 StopIteration,for 悄悄接住并结束
        break
print("--- for 的真身就是这样 ---")


# ========== 2. 可迭代 Iterable vs 迭代器 Iterator(面试第一高频) ==========
# Iterable(可迭代):实现了 __iter__      —— 能被 for,能被 iter()
# Iterator(迭代器):实现了 __iter__ + __next__ —— 能被 next() 一个一个吐
nums2 = [1, 2, 3]
print(hasattr(nums2, "__iter__"), hasattr(nums2, "__next__"))   # True False → 列表只是"可迭代"
it2 = iter(nums2)
print(hasattr(it2, "__iter__"), hasattr(it2, "__next__"))       # True True → 这才是迭代器

# 记忆:list 是一整箱书,迭代器是从箱里取书的那只手
# 关系:iter(可迭代) → 迭代器;迭代器一定是可迭代的,反之不成立

# 迭代器是一次性的(面试常见坑):
it3 = iter([1, 2, 3])
print(list(it3))                 # [1, 2, 3]
print(list(it3))                 # [] —— 耗尽了!而 list(nums2) 随时能再来一遍


# ========== 3. 生成器:自己造迭代器最省事的写法 ==========
def countdown(n):
    print("开始")
    while n > 0:
        yield n                  # 在这里"暂停",把 n 交出去;下次 next 从这一行继续
        n -= 1
    print("结束")


print("调用 countdown(3):函数体一行都没执行(惰性!)")
gen = countdown(3)
print(next(gen))                 # 这一瞬才打印"开始",吐出 3
print(next(gen))                 # 从 yield 处继续,吐出 2
print(next(gen))                 # 1
# print(next(gen))               # 再要:先打印"结束",然后 StopIteration

for x in countdown(3):           # for 会替你接住 StopIteration
    print("for:", x)


# ========== 4. 生成器表达式 vs 列表推导:() 惰性,[] 立即 ==========
squares_list = [x * x for x in range(1_000_000)]   # 立刻全算完,整块占内存
squares_gen = (x * x for x in range(1_000_000))    # 只是个"公式",几乎不占内存
print(sys.getsizeof(squares_list))                 # 八百多万字节
print(sys.getsizeof(squares_gen))                  # 一百字节上下
print(sum(x * x for x in range(100)))              # 边产生边消费的场景,天生一对


# ========== 5. 实战:无限序列 / 大文件流式处理 / yield from ==========
def fib():
    a, b = 0, 1
    while True:                  # 无限!但没人 next 它就不算,零压力
        yield a
        a, b = b, a + b


f = fib()
print([next(f) for _ in range(10)])


def read_large(path):
    with open(path, encoding="utf-8") as fp:   # 文件操作第 9 课讲
        for line in fp:          # 文件对象本身就是迭代器:一行一行读,10GB 也不撑爆内存
            yield line.strip()


def chain(a, b):
    yield from a                 # 委托:把另一个可迭代对象整个"接进来"
    yield from b


print(list(chain([1, 2], "ab"))) # [1, 2, 'a', 'b']


# ========== 6. 让自己的类也能 for(面试会问) ==========
class Countdown:
    def __init__(self, n):
        self.n = n

    def __iter__(self):          # for 每次开始,都来这要一个"新的手"
        return iter(range(self.n, 0, -1))
        # 也可以用生成器实现:yield from range(self.n, 0, -1)


print(list(Countdown(5)))        # [5, 4, 3, 2, 1]
```

## 第 9 课 · 09_文件操作.py — 文件操作(会用即可)

**目标**:会 `with open` 读写文本、会 json 读写、知道 Windows 编码坑。到此为止,别深钻。

**新概念**:

- `with open(...) as f` = Java 的 try-with-resources,块结束自动 close(哪怕中途抛异常)——**永远用 with,永远带 `encoding="utf-8"`**:Windows 默认编码是 GBK,不写迟早乱码/报错
- 模式:`r` 读(默认)/ `w` 覆盖写 / `a` 追加 / `b` 二进制,可组合(`rb`、`w+`)
- 读的三姿势:`read()` 整个读成字符串 / `readlines()` 读成行列表 / **`for line in f` 逐行迭代(最推荐——文件对象本身就是迭代器,和第 8 课闭环了)**
- JSON 两对:`json.dump/load` 走文件,`json.dumps/loads` 走字符串;`ensure_ascii=False` 让中文原样存——阶段 1 会话存盘、阶段 3 向量库持久化,核心就是这两段
- `pathlib.Path`:现代路径写法,用 `/` 拼路径自动跨平台,`read_text()` 小文件一步读完

```python
import json
from pathlib import Path


# ========== 1. 写:永远 with open,永远 encoding="utf-8" ==========
with open("demo.txt", "w", encoding="utf-8") as f:      # w = 覆盖写(没有就创建)
    f.write("第一行\n")
    f.writelines(["第二行\n", "第三行\n"])               # writelines 不会帮你加换行

with open("demo.txt", "a", encoding="utf-8") as f:      # a = 追加(文件不存在也会创建)
    f.write("第四行(追加的)\n")


# ========== 2. 读的三种姿势 ==========
with open("demo.txt", encoding="utf-8") as f:
    whole = f.read()                 # 姿势 1:整个读成一个大字符串(小文件用)
print(whole)

with open("demo.txt", encoding="utf-8") as f:
    lines = f.readlines()            # 姿势 2:读成"行列表"(文件大会爆内存,慎用)
print(lines)

with open("demo.txt", encoding="utf-8") as f:
    for line in f:                   # 姿势 3(最推荐):文件对象是迭代器,一行一行读——第 8 课!
        print(repr(line))            # 每行末尾带着 \n,处理前常要 strip()


# ========== 3. JSON:阶段 1 会话存盘、阶段 3 向量库持久化,核心就这两段 ==========
data = {"model": "glm-4", "history": [{"role": "user", "content": "你好"}]}

with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)   # ensure_ascii=False:中文原样存,不转 \uXXXX

with open("data.json", encoding="utf-8") as f:
    loaded = json.load(f)

print(loaded["model"], loaded["history"][0]["content"])


# ========== 4. pathlib:现代路径写法,会用即可 ==========
p = Path("demo.txt")
print(p.read_text(encoding="utf-8").splitlines()[0])   # 小文件一步读完

q = Path(".") / "sub" / "data.json"                     # 用 / 拼路径,自动跨平台
print(q)

print(sorted(x.name for x in Path(".").glob("*.json"))) # 列当前目录的 json 文件名
```

**自测**:

1. `"w"` 和 `"a"` 的区别?同一个文件用 `"w"` 连 open 两次,内容会怎样?
2. 把所有 open 里的 `encoding="utf-8"` 删掉再跑一次,你机器上出什么事?(实验完恢复)
3. `json.dump` 不写 `ensure_ascii=False`,打开 data.json 看看中文变成什么样了?
4. with 块结束时自动发生了什么?对应 Java 的哪个语法?
5. (连第 8 课)读 10GB 日志该用哪个姿势,为什么?

## 常见报错速查

| 报错 | 原因 | 解决 |
|---|---|---|
| `TypeError: Can't instantiate abstract class ...` | 抽象方法没实现全 | 检查子类是否实现了所有 `@abstractmethod` |
| `TypeError: ... missing 1 required positional argument: 'self'` | 没通过实例调方法 | `t.invoke(x)`,不是 `BaseTool.invoke(x)` |
| `UnboundLocalError` | 闭包里改外层变量没写 `nonlocal` | 加 `nonlocal` |
| `StopIteration`(自己写的循环里) | 手动 `next()` 超过了元素个数 | 用 for,或 `next(it, 默认值)` |
| `UnicodeDecodeError: 'gbk' codec ...` | Windows 下 open 忘了 encoding | 所有 open 都带 `encoding="utf-8"` |
| `TypeError: unhashable type: 'list'` | dict 的 key 或 set 的元素用了 list | 换成 tuple |
| `AttributeError: 'xxx' object has no attribute 'yyy'` | 对象类型和你想的不一样 | `print(type(x), x)` 先看它到底是谁 |
| `TypeError: 'NoneType' object is not callable` | 函数忘了 return,返回值被当函数用 | 检查 wrapper / 工厂函数的 return |

**卡住的标准动作**:读报错最后一行 → 按行号定位 → 超过 30 分钟,把代码 + 完整报错 + 你跑的原话,一起贴给 ZCode。
